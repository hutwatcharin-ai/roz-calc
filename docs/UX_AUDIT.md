## 1. ข้อค้นพบ

### F1 — บนมือถือ ทุกหน้าเสียพื้นที่ 248px ให้กับส่วนหัวก่อนเนื้อหาจะเริ่ม

**หลักฐาน: Measured** — `<h1>` ของทุกหน้าอยู่ที่ y=248px เท่ากันหมด บน viewport สูง 900px
คิดเป็น **28% ของหน้าจอแรก** หมดไปกับแถบซ้อนกัน 4 ชั้น: topbar โลโก้+ค้นหา → เมนูหลัก 4 ลิงก์ →
เมนูหมวด 5-6 ลิงก์ → แถบตัวละครที่มีประโยคยาว 2 บรรทัด

**ผลกับผู้ใช้** หน้าจอแรกที่ควรตอบว่า "ที่นี่คืออะไร ทำอะไรได้" กลายเป็นเมนู
**ความเชื่อมั่น: สูง** วัดจากหน้าจริงทั้ง 8 หน้า ค่าตรงกันทุกหน้า

### F2 — หน้าตีบวก เครื่องมืออยู่ใต้ขอบจอ เพราะมีกล่องหมายเหตุคั่น 2 กล่อง

**หลักฐาน: Measured** — h1 ที่ 248px แต่การ์ดเครื่องมือแรกอยู่ที่ 721px และ
**ช่องกรอกแรกอยู่ที่ 794px** บนจอสูง 900px คือเกือบสุดขอบพอดี
ระหว่างนั้นคือกล่อง "ที่มาของตัวเลข" กับ "สิ่งที่เว็บนี้ยังตอบไม่ได้" รวม 473px

**ผลกับผู้ใช้** คนที่มาเพราะอยากรู้ว่า +7 ต้องเตรียมเท่าไร ต้องเลื่อนผ่านคำอธิบายที่มาของข้อมูลก่อน
**สาเหตุ** เอกสาร UX ข้อ 8.3 จัดลำดับไว้ว่า เจตนาผู้ใช้ → ข้อมูลที่ใช้ตัดสินใจ → ปุ่มหลัก →
ข้อมูลสร้างความเชื่อถือ · หน้านี้เอาข้อ 4 ขึ้นก่อนข้อ 1
**ความเชื่อมั่น: สูง**

### F3 — หน้ามอนตอบคำถาม "ตีด้วยอะไรดี" สามครั้ง และเอาข้อสรุปไว้ท้ายสุด

**หลักฐาน: Measured** — ตำแหน่งหัวข้อบนมือถือ
- 645px "อาวุธธาตุไหนแรงกับตัวนี้" (ตาราง 10 แถว)
- 1,251px "อาวุธชนิดไหนตีตัวนี้ได้เต็ม" (ตาราง 20 แถว)
- **2,271px "สรุป: ตีตัวนี้ด้วยอะไรดี"** ← ข้อสรุปของสองตารางข้างบน

ผู้ใช้ต้องเลื่อนผ่าน 30 แถวของตารางดิบ ก่อนถึงบรรทัดที่บอกคำตอบ
**ผลกับผู้ใช้** คนส่วนใหญ่จะอ่านตารางแรกแล้วตัดสินใจเลย ซึ่งเป็นการตัดสินใจจากครึ่งเดียวของข้อมูล —
ซึ่งเป็นความผิดพลาดที่หน้าสรุปสร้างขึ้นมาเพื่อป้องกันพอดี
**ความเชื่อมั่น: สูง** · **นี่คือของที่ผมเพิ่งเพิ่มเข้าไปเอง**

### F4 — หน้ามอนสูง 6.1 หน้าจอ และของที่คนมาดูอยู่ลึกสุด

**หลักฐาน: Measured** — ความสูงรวม 5,475px = 6.1 จอมือถือ · "ของที่ดรอป" อยู่ที่ 3,512px (3.9 จอ)
· "จุดเกิด" ที่ 4,329px · ไม่มีทางลัดไปหัวข้อไหนเลย ต้องเลื่อนอย่างเดียว
**ความเชื่อมั่น: สูง** ว่าตำแหน่งเป็นแบบนี้ · **ปานกลาง** ว่าดรอปคือสิ่งที่คนมาดูมากที่สุด
*(Inferred จากชื่อหน้าและจากที่ `/drop-finder` เป็นเมนูหลัก ไม่มีข้อมูลคลิก)*

### F5 — หัวหน้าเว็บถูกคัดลอกซ้ำ 18 ครั้งเป็น inline style และไม่ย่อบนมือถือ

**หลักฐาน: Observed** — `grep` เจอ `<h1 style={{ fontFamily: '"Chakra Petch"...', fontSize: 32 }}>`
เหมือนกันเป๊ะใน 18 ไฟล์ · ขนาดตายตัว 32px ไม่ใช่ `clamp()` ทั้งที่ token `--shell` ในไฟล์เดียวกันใช้ `clamp()` อยู่แล้ว
**ผลกับผู้ใช้** ชื่อหน้ายาว ๆ อย่าง "หาจุด AFK ปลอดภัย" กินสองบรรทัดบนจอแคบ
**ผลกับงาน** แก้สไตล์หัวหน้าทีเดียวไม่ได้ ต้องไล่แก้ 18 จุด

### F6 — มีระบบตารางสองระบบที่ทำตัวคนละอย่างบนมือถือ

**หลักฐาน: Observed (CSS) + Measured (ความกว้างจริง)**
- `.data-table` มี media query ที่ 720px แปลงเป็นการ์ดซ้อน แต่ละช่องมีป้ายกำกับของตัวเอง — ใช้ในหน้าฐานข้อมูลทั้ง 6 หน้า **ทำงานดี**
- `.stat-table` กับ `.eltable` **ไม่มี** อะไรแบบนั้นเลย ได้แค่กล่อง `overflow-x: auto` ครอบ
- ผลที่วัดได้: หน้าตีบวกบนจอ 390px มีตารางกว้าง 562px อยู่ในกล่องที่ต้องเลื่อนซ้ายขวา

เครื่องมือใหม่ทุกหน้า (ตีบวก / EXP / ธาตุ / ขนาด / ตีด้วยอะไรดี) ใช้ระบบที่ไม่ได้รับการดูแลบนมือถือ
**ความเชื่อมั่น: สูง**

### F7 — กล่องหมายเหตุดังเท่าเนื้อหา และซ้อนกันได้ 2-3 กล่อง

**หลักฐาน: Observed** — `.ceiling-note` เป็นพื้นทึบ + เส้นขอบสีเน้น น้ำหนักสายตาเท่ากับการ์ดเนื้อหา
หน้าตีบวกมี 3 กล่อง หน้า EXP มี 2 กล่อง วางติดกัน
**ผลกับผู้ใช้** เอกสาร UX ข้อ 10.3 เรียกว่างบความซับซ้อน — ทุกอย่างสำคัญเท่ากัน แปลว่าไม่มีอะไรสำคัญ
และผู้ใช้เรียนรู้ที่จะข้ามกล่องพวกนี้ทั้งหมด รวมถึงกล่องที่เป็นคำเตือนจริง ๆ

### F8 — แถบตัวละครใช้ประโยคยาวเต็มความกว้างทุกหน้า ทั้งที่เป็นตัวเลือก

**หลักฐาน: Observed** — "ยังไม่รู้ว่าคุณเล่นอะไร — กรอกแล้วเว็บจะบอกได้ว่ามอนตัวไหนอันตรายกับคุณ
และคุณตีได้กี่ตัวต่อชั่วโมง" กินสองบรรทัดบนมือถือ ปรากฏบนทุกหน้ารวมถึงหน้าที่ไม่ได้ใช้ค่าตัวละครเลย
(เช่น ตารางธาตุ ตารางขนาด EXP)
**ความเชื่อมั่น: สูง**

## 2. สรุปปัญหา

> ผู้เล่นที่เปิดเว็บบนมือถือ ต้องการคำตอบของงานที่ตั้งใจมาทำ
> แต่หน้าจอแรกถูกใช้ไปกับเมนูและคำอธิบายที่มาของข้อมูล
> ทำให้ต้องเลื่อนหลายจอกว่าจะเจอเครื่องมือ และบางหน้าเจอข้อสรุปหลังจากตัดสินใจไปแล้ว

**เป้าหมายที่วัดได้**

- ทุกหน้าเครื่องมือ: **ช่องกรอกแรกอยู่เหนือ 700px** บน viewport 390×900 (ตอนนี้หน้าตีบวก 794px)
- หน้ามอน: **ข้อสรุปมาก่อนตารางที่มันสรุป** (ตอนนี้มาหลัง 1,626px)
- **ระบบหัวหน้าเดียว** ใช้ร่วมทุกหน้า ขนาดปรับตามจอ (ตอนนี้ copy-paste 18 จุด)
- **ตารางทุกชนิดอ่านได้บนจอ 390px โดยไม่ต้องเลื่อนซ้ายขวา** (ตอนนี้ `.stat-table` / `.eltable` ต้องเลื่อน)

**ข้อจำกัดที่ห้ามพัง**

- ตัวเลขทุกตัวยังต้องบอกที่มาได้ — ย้ายที่วางได้ ตัดทิ้งไม่ได้
- คำเตือนที่เป็นเรื่องความปลอดภัย (ธง AFK, ดรอปช่วงที่ไม่ยืนยัน) ต้องไม่ถูกลดชั้นไปเท่ากับหมายเหตุทั่วไป
- หน้าเครื่องมือต้อง render ฝั่ง server เหมือนเดิม — เคยพลาดมาแล้วหนึ่งรอบที่หน้า AFK ขึ้นแต่หัวข้อ
- 401 เทสต์ต้องเขียวเหมือนเดิม

# รอบที่ 2 — 28 สิงหาคม 2569 (หลัง rollout) ตรวจตาม checklist ของ ui-ux-pro-max

วัดบน production ที่ 320px และ 375px 10 หน้า + คำนวณ contrast จาก token จริง

## ผ่านแล้ว (Measured)
- ปุ่ม/ช่องกรอก 40 ตัว ต่ำกว่า 44px = 0 · ระยะห่างระหว่างปุ่ม < 8px = 0
- h1 หน้าละ 1 · ไม่มีการข้ามระดับหัวข้อ · รูปทุกรูปมี alt · ไม่มี emoji ใช้แทนไอคอน (✓ ที่เจอเป็น glyph มี aria-hidden + ข้อความกำกับ)
- ทุก element ที่คลิกได้มี cursor: pointer · มี focus ring · มี prefers-reduced-motion
- ลิงก์ไม่มีข้อความกลาง ๆ แบบ "คลิกที่นี่" · ตัวกรองอยู่ใน URL (deep link + back ทำงาน)

## แก้ในรอบนี้
- **`--faint` 4.44:1 บนพื้น / 3.84:1 บน panel-2** ต่ำกว่า 4.5 ทุกพื้นผิว และเป็นสีของหัวตาราง/บรรทัดที่มา/ตัวนับทั้งเว็บ → #8F86C4 (5.16:1 บนพื้นเข้มสุด)
- หัวตาราง `.eltable` 11px (22 ช่องบนหน้าตีบวก) ที่เดียวที่ต่ำกว่า 12px → 12px
- "Ctrl+K" บนปุ่มค้นหาดันจอ 320px ล้น 41px และไร้ความหมายบนมือถือ → ซ่อนบน touch/ต่ำกว่า 360px
- **ไม่มี aria-live ที่ไหนเลย** → role=status ที่ตัวนับผลค้นหา, role=alert ที่ error ของแถบตัวละคร
- รูปในตาราง 50 รูป/หน้า โหลดทันทีทั้งหมด → loading="lazy" (9 จุด) หน้ารายละเอียดยังโหลดทันที
- ฟอร์มเลเวลหน้าแรกไม่ wrap ล้นจอ 320px → ใช้ `.filterbar`

## ควรเพิ่ม (เรียงตามผลต่อผู้ใช้ / ต้นทุน)
1. **หน้าแบ่งแบบมีตัวเลข** — ตอนนี้มีแค่ ก่อนหน้า/ถัดไป + "หน้า 3/11" · เพิ่ม "แสดง 101–150 จาก 524" และกระโดดไปหน้าท้าย
2. **เรียงลำดับในหน้ารายการ** — มอนเรียงตามเลเวลตายตัว ไม่มีทางเรียงตาม EXP/HP หรือชื่อ (ข้อกำหนด Sort ของ UX guideline)
3. **breadcrumb บนหน้ารายละเอียด** — "ฐานข้อมูล › มอนสเตอร์ › Poring" ทดแทน back ที่หายเมื่อเข้าจากลิงก์ภายนอก
4. **"เพิ่งดู" / "เพิ่งค้น"** ใน localStorage — recognition over recall คนเปิดมอนตัวเดิมซ้ำ
5. **เมนูล่างบนมือถือ ≤ 5 ปุ่ม** (หาจุดตี / ค้นดรอป / ฐานข้อมูล / เครื่องมือ / ค้นหา) — ทางเดียวที่ปลด 100px+ จากด้านบนโดยไม่ซ่อนอะไร · เป็นการเปลี่ยนโครง ทำเป็นรอบของมันเอง
6. **GA4** — ทุกข้อที่ยังติดป้าย Inferred (คนเปิดหน้ามอนมาดูอะไร) ต้องมีข้อมูลจริงก่อนตัดสินใจรอบถัดไป
