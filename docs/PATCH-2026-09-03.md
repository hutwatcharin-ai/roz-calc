# Runbook — แพทช์ 3 ก.ย. 2569 (cap 60 / 2nd Job / Episode 1-2)

เซิร์ฟเปิดใหม่ ~11:15 น. (ไทย) — รอ rozerodb อัปเดตหน้าของเขาก่อน (ปกติภายในวันเดียวกัน) เช็คได้จาก
`https://rozerodb.com/sitemap.xml` ว่ามี URL มอน/แมพใหม่โผล่ไหม แล้วค่อยเริ่ม

หน้าสรุปแพทช์ที่ต้องอัปเดตตอนจบ: `app/news/patch-2026-09-03/page.tsx` (section "หลังแพทช์ลง" + `MODIFIED`)

## ลำดับ

1. **Re-crawl rozerodb** (ทั้ง sitemap, ~30 นาที, 8 concurrent)
   ```
   cd docs && node rozerodb-export/crawl-rozerodb.mjs
   ```
   ผลลง `docs/rozerodb-export/data/*.jsonl` + `manifest.json` (ดู failures) — โฟลเดอร์นี้ **อยู่ใน repo** (ต่างจาก midgardhub-export ที่ห้ามเข้า)

2. **Import แบบ dry ก่อน** ดูว่าจะเพิ่ม/เติมอะไร
   ```
   npx tsx scripts/import-rozerodb-export.ts --dry
   ```
   กติกาสคริปต์: แถวเดิมเติมเฉพาะ NULL ไม่ทับค่าที่มี · แถวใหม่ insert · ดรอปที่ resolve ชื่อมอนไม่ได้ = นับแล้วรายงาน ไม่เดา
   ต้อง export `NEXT_PUBLIC_SUPABASE_URL` + `SUPABASE_SERVICE_ROLE_KEY` ก่อน (อยู่ใน .env.local)

3. **Import จริง** เมื่อ dry ดูสมเหตุสมผล (จำนวนมอนใหม่ควรตรงกับดันเจี้ยนใหม่ 4 แห่ง ไม่ใช่หลักพัน)

4. **เควสใหม่** — `scripts/import-quests.ts` แล้วแปลไทย: เควสใหม่จะมี `name_th/objective_th/description_th` = NULL
   - ดึงลิสต์ที่ยังไม่แปล: `select id, name, objective, description from quests where name_th is null`
   - แปลมือ/ช่วยแปล แล้ว apply ผ่าน `scripts/apply-quest-translations.ts` (ไฟล์ต้นทาง `data/`)
   - NPC ของเควสใหม่: crawl `/npcs/<code>` ของ rozerodb เหมือนรอบ 1 ก.ย. → `quest_npcs` + sprite `public/images/npcs/`

5. **ของใหม่ที่เป็น equipment** (Raid Party Equipment) — ใช้ pipeline เดิม:
   - slots: parse จาก rozerodb export (`data/equipment-slots.json` pattern)
   - อาชีพ: `equippable_classes` มาจาก rozerodb; ถ้าว่างเติมจาก midgardhub CSV (local only)
   - ราคาขาย: sync จากหน้า rozerodb รายตัว (`scratchpad/sync-equip-prices.mjs` pattern, resume file)
   - ตำแหน่งคอสตูมถ้ามี: `sync-costume-types.mjs` pattern

6. **Cash Shop** — recapture ราคา (แพทช์ใหญ่มักเปลี่ยน) → อัปเดต `cash_shop_items` + วันที่ในหน้า cash-shop (`ราคา ณ …`)

7. **แมพใหม่** — ถ้า rozerodb มีหน้าแมพใหม่ที่ `map_stats` เราไม่มี: เช็ค `monster_spawns` ว่ามอนใหม่ผูกแมพไหน → หน้า `/database/maps/[code]` จะขึ้นเองเมื่อมี spawn (sitemap อ่านจาก `map_stats`)

8. **ตรวจ** — `npx vitest run` · `npx next build` · `next start -p 3177` ดูหน้ามอนใหม่ 2–3 ตัว + หน้าแมพใหม่ + เควสใหม่ 1 ตัว · ตัวเลข hit_100/flee_95 ของมอนใหม่ (midgardhub CSV ต้อง re-export ถ้าเขามีมอนใหม่ — ถ้ายังไม่มี ปล่อย NULL แสดง "—")

9. **Deploy** (push gated + Coolify) → `rm -rf .next/cache/fetch-cache` ไม่จำเป็นบน prod เพราะ redeploy บัสต์เอง
   - ⚠️ **Cloudflare cache HTML ไว้ 24 ชม. (Cache Rule `cache-html`) — redeploy ไม่บัสต์ CF** ต้องกด Caching → Configuration → **Purge Everything** ทุกครั้งหลัง deploy ไม่งั้นหน้าเดิมโชว์ของเก่าถึงวันถัดไป (เจอจริง 2 ก.ย.: /about ค้าง Age 8,474 วิ) — ทางถาวร: CF API token scope Cache Purge ใส่ post-deploy hook ใน Coolify

10. **หลัง deploy**
    - `NEXT_PUBLIC_SITE_URL=https://rozerothai.com npx tsx scripts/ping-indexnow.ts`
    - อัปเดตหน้าแพทช์: section "หลังแพทช์ลง" → ลิงก์เข้ามอน/แมพ/เควสใหม่ + `MODIFIED` เป็นเวลาจริง
    - farm-guide bracket 46–60 จะเปลี่ยนเอง (ISR 24 ชม. — redeploy บัสต์แล้ว)
    - badge "อัปเดตล่าสุด" หน้าแรกเด้งเป็น "เมื่อสักครู่" เอง (updated_at)
    - เอาชิปแพทช์ออกจาก explore row หน้าแรกเมื่อพ้น ~1 สัปดาห์ (`app/page.tsx`)
