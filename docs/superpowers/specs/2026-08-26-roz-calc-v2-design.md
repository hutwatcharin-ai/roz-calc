# ROZ Calc v2 — ขยายฐานข้อมูลจากของที่มีในมือ

**สถานะ:** ร่าง รอ user รีวิว
**ต่อจาก:** `2026-08-25-roz-calc-design.md` (v1 — live อยู่แล้ว)

## 1. ที่มาและเป้าหมาย

v1 ปล่อยขึ้น production แล้ว มี 3 ฟีเจอร์ (Farming Finder, Drop Finder, Monster/Item DB Browser) + Global Search
เป้าหมาย v2: เพิ่มฟีเจอร์ให้ใกล้เคียงเว็บคู่แข่ง (midgardhub, rozerodb) **โดยใช้เฉพาะข้อมูลที่มีสิทธิ์ใช้อยู่แล้ว** ไม่ต้องหาข้อมูลใหม่จากแหล่งที่ติดข้อจำกัด

## 2. สิ่งที่สำรวจแล้วและตัดทิ้ง — พร้อมหลักฐาน

สำรวจฟีเจอร์ของ midgardhub + rozerodb ครบ (26 ส.ค.) พบ gap ~15 อย่าง แบ่งเป็น 4 กลุ่ม กลุ่มที่ตัดทิ้งพร้อมเหตุผล:

### กลุ่มเครื่องมือคำนวณ (refine simulator, forge, brewing, arrow crafting, affix, EXP calc, skill tree) — **ตัดทิ้งทั้งกลุ่มในคลื่นแรก**

> **📌 อ่าน §3.9–§3.12 และ §3.16 ประกอบ** — ข้อสรุปในหัวข้อนี้ถูกปรับทีหลัง (26 ส.ค.): สูตรของ Zero ใช้ Renewal จริง แค่ *ข้อมูล* ที่ถูกดัดแปลง → **Stat Calculator กู้กลับได้** (§3.10, §3.12)
>
> **ส่วน refine simulator — ยืนยันว่าไม่ทำ** (§3.16) ระหว่างทางเคยเขียนว่า "ปลดล็อกได้ถ้า user เก็บ % มาให้" **ข้อนั้นถูกยกเลิกแล้ว** เหตุผลเต็มอยู่ใน §3.16 · ที่ยังตัดทิ้งเหมือนเดิมคือตัวที่ต้องพึ่งข้อมูลที่ยังไม่มีต้นทางที่เชื่อถือได้ (affix pool, skill tree, forge recipe, refine)

เหตุผลที่ตัดตั้งแต่แรก: ต้องใช้ตัวเลข/สูตรที่เราไม่มี ตรวจแหล่งที่เป็นไปได้ครบทุกทางแล้ว ไม่มีทางที่ใช้ได้:

| แหล่ง | ผลตรวจ |
|---|---|
| rAthena (GPL-3.0, open source) | มีไฟล์ครบ (`refine.yml`, `produce_db.txt`, `item_randomopt_db.yml`, `skill_tree.yml`, `job_exp.yml`, `level_penalty.yml`) แต่ deep-research ยืนยัน 3-0 ว่า **rAthena ไม่มีโหมด Zero เลย** — มีแค่ pre-renewal/renewal ทั้งระดับ compile flag (`renewal.hpp` ไม่มีคำว่า ZERO) และระดับข้อมูล (`db/` มีแค่ `pre-re`, `re`) สิ่งที่เรียกว่า "Zero support" คือ packet layer ของ client (`PACKETVER_ZERO`) ล้วนๆ ไม่แตะข้อมูลเกมสักไฟล์ ค่าที่ได้จึงเป็นค่า **renewal ไม่ใช่ Zero** |
| Divine-Pride API | มี server alias `GZero`/`kROZ`/`twROZ` แยกจริง แต่ Usage Guidelines ห้ามตรงตัว: *"Don't try to mirror the whole database... It isn't meant to let a third party stand up a competing copy of this site's database"* + *"scripted bulk id enumeration... will get a key revoked"* — และต่อให้ไม่ติดข้อนี้ endpoint มีแค่ `Monster`/`Item`/`Skill`/`Efst`/`LatestUpdates` **ไม่มี refine/forge/affix/EXP** อยู่ดี |

| ragnarokzero.wiki, ragnarokze.ro, assets.twroz.wiki | robots.txt ระบุ `User-agent: ClaudeBot / Disallow: /` |
| rozerodb.com | ~~robots.txt ของเขาเอง `Disallow: /api/` (หน้า tool ไม่มีตัวเลขใน HTML โหลดจาก API)~~ **← ข้อความนี้ผิด แก้ 26 ส.ค.** ดู `docs/rozerodb-tools-audit.md` §3: ทดสอบด้วย curl โดยไม่รัน JS แล้วพบว่าตัวเลขถูก server-render มาในหน้าเลย (หน้า refine 22KB มีค่าธรรมเนียมและความน่าจะเป็นสะสม · หน้า affixes 114KB มีพูลและช่วงค่าครบ) robots.txt เขาคือ `Allow: /` + `Disallow: /api/` เท่านั้น การเปิดอ่านหน้าเว็บไม่ได้ถูกห้าม<br>**แต่ยังไม่ลอกอยู่ดี ด้วยเหตุผลที่แข็งกว่า:** (1) ดูดตารางเขามาทั้งชุด = ทำสำเนาฐานข้อมูลเว็บอื่น และเราจะผิดตามเขาทุกครั้งที่เขาผิด (2) **เขาเองประกาศว่าหลายชุดยังไม่ยืนยัน** — affix ยังตรวจกับไฟล์เกมอยู่, forge มาจากดูสตรีม TwRO, alchemist ยังไม่ยืนยันสกิลตัวหนึ่ง → ลอกมาคือลอกความไม่แน่นอนมาด้วย |
| `data.grf` (game client) | container เข้ารหัส signature `"Event Horizon"` ไม่ใช่ GRF มาตรฐาน — ไม่ reverse-engineer |

**หลักฐานเพิ่มจากฝั่งผู้เล่น (ซับ YouTube 29 คลิป, 26 ส.ค.):** Zero **ไม่มีขั้นบันได EXP ตามส่วนต่างเลเวลเลย** (ตีมอนห่างแค่ไหนก็ได้ EXP เต็ม) หักเฉพาะดรอป 50% เมื่อห่างเกิน 40 เลเวล — ขัดกับตาราง `level_penalty.yml` ของ rAthena renewal ชัดเจน (renewal ให้โบนัส 140% ที่ +10 และหน้าผา 40% ที่ +16) **ยืนยันว่าค่า renewal ใช้กับ Zero ไม่ได้จริง**

**นัยสำคัญ:** Farming Finder ปัจจุบันเรียงตาม EXP/HP ดิบโดยไม่ใส่ค่าปรับเลเวล — **ถูกต้องแล้วสำหรับ Zero ไม่ต้องแก้**

## 3. Scope ของ v2 — 18 งาน แบ่ง 2 คลื่น (ดูรายการเต็มที่ §3.17)

scope โตขึ้นสองรอบระหว่างการออกแบบ (จาก 6 เป็น ~17 ตอนสำรวจคู่แข่ง แล้วปรับอีกครั้ง 26 ส.ค. หลังอ่านเอกสารวิจัย 3 ฉบับ) — **§3.17 คือรายการงานที่ผูกพัน** หัวข้อย่อยด้านล่างคือรายละเอียดของแต่ละงาน

งานดีไซน์ที่ตัดสินใจแล้ว (รายละเอียด §6): เมนูสองชั้น, หน้าแรกแบบผสม, ขยาย Global Search ครบ 6 อย่าง, ไฮไลต์เมนูหน้าปัจจุบัน, แถวการ์ดบนมือถือ, หน้ามอนสองคอลัมน์

### 3.0 Data fix: เพิ่ม `description` ให้ตาราง items (ต้องทำก่อนข้ออื่น)

ตาราง `items` ปัจจุบัน**ไม่มีคอลัมน์ description** ทั้งที่ raw data มีครบ 1,300/1,300 — หน้า item detail จึงโชว์แค่ ATK/เลเวล/อาชีพ ไม่มีคำอธิบายเอฟเฟกต์เลย และ Cards browser (ข้อ 3.3) จะไม่มีอะไรให้แสดงถ้าไม่มีข้อมูลนี้

- migration `0003_item_description.sql`: `alter table items add column description text;`
- `transformItem` เพิ่ม `description: raw.description?.text ?? null`
- รัน import ใหม่ (upsert ทับของเดิม ไม่ต้องล้างตาราง)
- หน้า item detail แสดง description (คงบรรทัดใหม่ด้วย `white-space: pre-line`)

### 3.1 Skills browser (`/database/skills`)

ข้อมูลพร้อมใน DB แล้ว 851 แถว ไม่มีหน้าเว็บใช้เลยตั้งแต่ v1

- **List:** ชื่อ + ไอคอน + ชนิด (active/passive) + max level + อาชีพที่ใช้ได้
- **ค้น/กรอง:** ค้นชื่อ, กรองตามอาชีพ (จาก `classes` array), กรองตามชนิด
- **Pagination:** 50/หน้า แบบเดียวกับหน้าอื่น
- **ไม่ทำหน้า detail** — ข้อมูลที่มีต่อสกิล (ชื่อ/ชนิด/max level/ธาตุ/อาชีพ/ไอคอน) น้อยเกินกว่าจะเปิดเป็นหน้าเดี่ยว แสดงครบในแถวรายการได้เลย
**🔄 แก้ความเข้าใจเดิม (26 ส.ค. — ดู `docs/skill-tree-research.md` §5.11):** เคยเขียนว่า "418/851 ไม่มีอาชีพผูก = ข้อมูลต้นทางไม่สมบูรณ์" — **ไม่ถูกต้อง**

ความจริง: ส่วนใหญ่ของ 418 รายการนั้น **ไม่ใช่ข้อมูลขาด แต่เป็นเนื้อหาที่ยังไม่เปิดในเซิร์ฟ** (สกิลคลาส 3 เช่น Adoramus/Aimed Bolt/Abundance, สกิลโฮมุนคูลุส) และในไฟล์ยังมีอาชีพที่ไม่มีในเกม Zero เลย (Super Novice 52, Ninja 23, Gunslinger 22, Kagerou 22, Oboro 22, Rebellion 20, และคลาส 3 อย่าง Lord Knight / Paladin / Assassin Cross)

**ส่วนที่ตรงกับอาชีพจริงใน Zero มี 370 สกิล ครบทั้ง 19 อาชีพ** จำนวนต่ออาชีพสมเหตุสมผล (คลาส 1: Swordsman 11 · Mage 15 · Archer 7 · Thief 11 · Acolyte 16 · Merchant 12) — ตรงกับจำนวนสกิลคลาส 1 ที่รู้กันใน RO ทั่วไป เป็นสัญญาณว่าชุดนี้ครบ ไม่ใช่ขาด

**ผลต่อการออกแบบหน้า:**
- **กรองเหลือ 19 อาชีพที่มีจริงในเกมเป็นค่าเริ่มต้น** ไม่โชว์ 851 รายการรวด
- **แท็บแยก "ยังไม่เปิดในเซิร์ฟ"** สำหรับส่วนที่เหลือ พร้อมคำอธิบายว่าเป็นเนื้อหาที่ยังมาไม่ถึง Global — เปลี่ยนจาก "ข้อมูลเราไม่ครบ" เป็น "เรารู้ว่าอะไรยังไม่มา" ซึ่งมีค่าในตัวเอง
- ค่าที่ขาดจริง (ชนิดขาด 448, ธาตุขาด 691) ยังแสดง `—` ไม่เดา

**⛔ ต้องทำก่อน ไม่งั้นหน้าพัง:** ไอคอนสกิลทั้ง 851 เก็บ path เป็น `/assets/local/catalog/...` ซึ่งเป็น path ของ **rozerodb** → เปิดบนเว็บเราจะ **404 ทั้งหมด** ต้อง mirror มาเก็บเองก่อน (งานแบบเดียวกับรูปมอน 522 + รูปไอเทม 1,299 ที่ทำมาแล้ว) · ทางสำรอง: แสดงเป็นบล็อกสีตามธาตุ + อักษรย่อชื่อสกิล

**Skill tree planner ยังทำไม่ได้** — ขาด `requires[]` (เงื่อนไขสกิลที่ต้องลงก่อน) ซึ่งไม่มีเลยสักรายการ · ถ้าให้ลงแต้มโดยไม่มีข้อมูลนี้ ระบบจะบอกว่าลงสกิลได้ทั้งที่ในเกมลงไม่ได้ = **ให้คำตอบผิด ซึ่งแย่กว่าไม่มีฟีเจอร์** · แนวทาง UI เต็มรูปแบบเตรียมไว้แล้วใน `docs/skill-tree-research.md` §5 พร้อมลงมือทันทีที่ได้ข้อมูลจากไฟล์เกม

### 3.5 Element damage table (`/tools/elements`)

ตารางตัวคูณดาเมจธาตุโจมตี × ธาตุป้องกัน — เขียนเป็น constant ในโค้ด

- **⚠️ ป้ายเตือนถาวรแบบเดียวกับที่เคยใช้:** ค่านี้อ้างอิงกฎ RO มาตรฐาน **ยังไม่ยืนยันว่าตรงกับ Zero** (บทเรียนจากตาราง level penalty ที่ค่า renewal ขัดกับที่ผู้เล่น Zero รายงาน)
- **การตัดสินใจ:** ทำฟีเจอร์นี้ **พร้อมป้ายเตือนถาวร** (ไม่ตัดออก) เพราะตารางธาตุเป็นกลไกที่นิ่งที่สุดของ RO และผู้เล่นใช้อ้างอิงกันทั่วไป — ป้ายเตือนต้องมองเห็นชัดบนหน้า ห้ามซ่อนหรือทำให้ปิดได้ แบบเดียวกับที่ Stat Calculator เคยใช้
- เชื่อมกับหน้ามอนสเตอร์: หน้า monster detail แสดง "ธาตุนี้อ่อนต่ออะไร" จากตารางเดียวกัน

### 3.6 Farm planner (`/tools/farm-planner`)

บันทึกรายการมอนสเตอร์ที่วางแผนจะตี — ไม่ต้องใช้ข้อมูลใหม่ ไม่ต้อง login

- ปุ่ม "เพิ่มเข้าแผน" บนหน้า monster detail และแถวใน Farming Finder
- หน้า planner แสดงรายการที่บันทึกไว้ พร้อม EXP/HP, Zeny/ตัว, แมพที่เจอ, และผลรวม
- เก็บใน `localStorage` (ต่อเบราว์เซอร์) — ไม่มี backend, ไม่มีบัญชีผู้ใช้
- **ต้อง handle:** localStorage ใช้ไม่ได้ (private mode/ปิด site data) → หน้าต้องยังเปิดได้ แสดงข้อความว่าบันทึกไม่ได้ ไม่ใช่ crash

| `baseStats` (STR/AGI/VIT/INT/DEX/LUK) | ครบ 524 | หน้ารายละเอียดมอน |
| `magicAtkMin` / `magicAtkMax` | ครบ 524 | MATK ของมอน |
| `skills` (สกิลที่มอนใช้ + rate% + castTime + delay + target) | 456/524 | เตือนว่ามอนตัวนี้ใช้สกิลอะไร อันตรายแค่ไหน |

**งานที่ต้องทำ:** migration เพิ่มคอลัมน์ + แก้ `transformMonster` + import ใหม่ (upsert ทับ)
- `monsters`: `is_aggressive boolean`, `is_mvp boolean`, `loots_items boolean`, `size` (มีแล้ว), `matk_min/max int`, `str/agi/vit/int_/dex/luk int`
- ตารางใหม่ `monster_skills`: `monster_id, skill_name, skill_lv, rate, cast_time, delay, target, state`

## 3.8 ฟีเจอร์ "หาจุด AFK ปลอดภัย" — หน้าแยก (เพิ่ม 26 ส.ค.)

เกมนี้มี**บอทในตัวใช้ฟรีไม่จำกัด** ทำให้ "AFK ที่ไหนไม่ตาย" เป็นคำถามอันดับหนึ่งของผู้เล่น — เอกสาร YouTube อธิบายวิธีทำมือไว้ 4 ขั้น ซึ่งเว็บทำให้จบในหน้าเดียวได้ และ**ยังไม่มีเว็บคู่แข่งเจ้าไหนทำ** (midgardhub มี farming planner แต่ไม่กรองความปลอดภัย)

**ตัดสินใจ: แยกเป็นหน้าของตัวเอง** `/tools/afk-finder` ไม่ใช่ตัวกรองในหน้า Farming Finder
- เป็นคนละคำถามกันจริง — Farming Finder ตอบ *"ตีอะไรคุ้มสุด"* / AFK Finder ตอบ *"ทิ้งบอทตรงไหนแล้วกลับมาไม่ตาย"*
- input ต่างกัน (ต้องกรอกดาเมจต่อฮิตของตัวเอง) และลำดับการเรียงต่างกัน (ความปลอดภัยมาก่อน EXP)
- **เหตุผลด้านการโปรโมต:** หน้าที่ชื่อตรงกับปัญหาที่คนกำลังเจอ แชร์ในกลุ่มเกมได้ผลกว่าการบอกว่า "ไปติ๊ก checkbox ในหน้าแรก"

**สิ่งที่หน้านี้ทำ:**
1. กรอกเลเวล + ดาเมจต่อฮิต + ธาตุอาวุธ
2. **ตัดมอน `is_aggressive` ออกทั้งหมด** (สาเหตุหลักที่ตายตอน AFK)
3. เหลือเฉพาะมอนที่ **ตายใน 1 ฮิต** (`hp <= ดาเมจที่กรอก`) — เอกสารระบุว่านี่คือเงื่อนไขที่ผู้เล่นใช้จริง
4. แสดงสกิลที่มอนใช้ (จาก `monster_skills`) เตือนถ้ามีสกิลอันตราย
5. เรียงตาม EXP/HP ในกลุ่มที่ผ่านเกณฑ์ความปลอดภัยแล้ว

ต้องรอ 3.7 เสร็จก่อน เพราะใช้ `is_aggressive` + `monster_skills`

## 3.9 ตัวเลขกฎเกมที่ยืนยันแล้ว — เอาไปใช้ได้

จาก `docs/youtube-research-roz.md` (ผู้เล่นพูดตรงกันหลายคลิป):
- **ไม่มีขั้นบันได EXP** ตีมอนห่างเลเวลแค่ไหนก็ได้ EXP เต็ม → **Farming Finder ปัจจุบันเรียงตาม EXP/HP ดิบถูกต้องแล้ว ไม่ต้องแก้**
- **ดรอปหัก 50% เมื่อเลเวลห่างเกิน ±40** (ช่วง ±19 ไม่มีบทลงโทษเลย) → ใส่เป็นคำเตือนในหน้า Farming Finder / Drop Finder
- **EXP/HP เฉลี่ยทั้งเซิร์ฟ ~0.6** (ต้นเกม 0.7–0.8) → เปิดทางทำเครื่องมือ "ประมาณ EXP ต่อชั่วโมง" จาก DPS ที่ผู้ใช้กรอก

**อัตราตีบวก — ดู §3.16 (ข้อสรุปที่นี่ถูกแทนที่แล้ว):** user ทดสอบในเกมจริงเอง ยืนยัน **+1 ถึง +4 ติด 90% เท่ากันหมด** — หลักฐานชั้นดีที่สุดที่มี เพราะทดสอบตรงในเกม
- ~~"ตรงกับ Viva-Tz ไม่ใช่แบบไล่ระดับของ NCZ"~~ **← ผิด** §3.16 พบว่าอัตราแยกตามประเภทและระดับของ ทั้งสองช่องจึงพูดถูกคนละสาย · ค่าที่ user วัดตรงกับสาย Weapon Lv.1–3
- ~~"เก็บ +5..+20 มาแล้วจะปลดล็อก refine simulator"~~ **← ยกเลิก** ดู §3.16
- ทุกแหล่งตรงกันว่า: **แตกได้ตั้งแต่ +1** และ **เพดาน +20**

**⚠️ ยังห้ามเอาขึ้นเว็บ** — ที่เอกสารระบุเองว่าขัดกันและยังไม่มีใครทดสอบ: ปาร์ตี้ช่วยเก็บเลเวลไหม, EXP ปาร์ตี้แชร์ทั้งแมพหรือเฉพาะคนใกล้, แมพ PK มอนเกิดไวจริงไหม

## 3.10 ปรับข้อสรุปเรื่อง rAthena (สำคัญ — แก้ §2)

เอกสาร YouTube ระบุ: *"ฐานการคำนวณสเตตัสและดาเมจใช้ระบบ Renewal (STR/DEX/Flee/VCT ทำงานตามหลักเดิม) แต่ค่าสเตตัสมอนสเตอร์ ไอเทมที่ดรอป เนื้อเรื่อง และผังสกิลถูกดัดแปลงใหม่ทั้งหมด"*

ต้องแยกสองอย่างนี้ให้ขาดจากกัน:
- **สูตร (formula)** — ASPD, cast time, flee, ATK จาก STR = Renewal → **rAthena อ้างอิงได้**
- **ข้อมูล (data)** — อัตราตีบวก, ผังสกิล, สเตตัสมอน, affix pool = ดัดแปลงใหม่ → **ใช้ไม่ได้ ยืนตามข้อสรุปเดิมใน §2**

**ผลที่ตามมา:** Stat/Build Calculator ที่ลบทิ้งไปตอน v1 **มีเหตุผลให้กู้กลับได้แล้ว** ถ้าใช้เฉพาะสูตร Renewal — ต่างจากตอนลบที่เราไม่มีหลักฐานอะไรเลยว่าสูตรตรงไหม (ยังต้องคงป้ายเตือน เพราะเป็นคำบอกเล่าผู้เล่น ไม่ใช่เอกสารทางการ) · ส่วน refine simulator / skill tree **ยังทำไม่ได้เหมือนเดิม** เพราะเป็น data ไม่ใช่ formula

## 3.11 เกมคือแหล่งข้อมูลที่ดีที่สุด — และไม่ติดข้อจำกัดใดเลย (เพิ่ม 26 ส.ค.)

### 3.15.1 ธง "ปล่อยบอทได้ไหม" — ทั้งเว็บ ไม่ใช่หน้าเดียว

**แก้จาก §3.8** ที่วางป้าย Aggressive ไว้แค่ในหน้า AFK finder และหน้ามอนรายตัว — เอกสาร audit จัดข้อนี้เป็น**อันดับ 1 ของสิ่งที่ควรทำ** และเสนอให้ป้ายติดไปกับมอน**ทุกที่ที่มอนปรากฏ**

- ทุกแถวใน Farming Finder, ผลค้นหา, หน้ารายการมอนสเตอร์, หน้าแมพ, ผล Drop Finder

**เกณฑ์แบ่งระดับ — ต้องไม่เดา** จำนวนระดับขึ้นกับว่ารู้จักผู้เล่นหรือยัง:

| มีบริบทตัวละคร? | แสดงกี่ระดับ | เกณฑ์ |
|---|---|---|
| **ไม่มี** (ยังไม่กรอก / localStorage ใช้ไม่ได้) | **2 ระดับ** | `is_aggressive = false` → ปลอดภัย · `true` → เข้าตีเอง |
| **มี** (รู้เลเวล + อาชีพ) | **3 ระดับ** | ปลอดภัย = ไม่เข้าตีเอง · ระวัง = เข้าตีเองและ `atk_max < 20%` ของ HP ผู้เล่น · อันตราย = เข้าตีเองและ `atk_max >= 20%` ของ HP ผู้เล่น |

- HP ผู้เล่นคำนวณจาก `maxHp()` ใน `lib/formulas.ts` (มีอยู่แล้ว ผ่านเทสต์แล้ว)
- **ห้ามแสดง 3 ระดับตอนไม่มีบริบท** — เกณฑ์ "แรง/เบา" ไม่มีความหมายถ้าไม่รู้ว่าเทียบกับใคร การเดาให้ = ให้คำตอบผิด
- เกณฑ์ 20% เป็น**ค่าที่เราตั้งเอง ไม่ใช่ค่าจากเกม** → ต้องมี tooltip บอกตรงๆ ว่าคิดจากอะไร ผู้ใช้จะได้ตัดสินเองได้
- **กรองได้จากหน้ารายการ** ("ซ่อนมอนที่เข้าตีเอง") — ตัวกรองนี้ใช้ `is_aggressive` ล้วน ทำงานได้แม้ไม่มีบริบท
- เหตุผล: มอน active attack คือสาเหตุหลักที่ตายตอน AFK แล้วเสีย EXP 10% — และ **rozerodb ไม่แสดงข้อมูลนี้เลยทั้งที่อยู่ในไฟล์เกม**

### 3.15.2 บริบทตัวละครร่วม (localStorage) — ข้อได้เปรียบเชิงโครงสร้าง

เก็บ **เลเวล · อาชีพ · ดาเมจต่อครั้ง · ความเร็วโจมตี · บัฟที่ใช้** ไว้ที่เดียว ทุกหน้าอ่านค่าเดียวกัน ไม่ต้องมีระบบสมาชิก

ผลที่ตามมา:
- หน้ามอนสเตอร์แสดงเลยว่า **"ตัวนี้คุณตีกี่ทีตาย"** และ **"EXP ต่อชั่วโมงถ้ายืนตีตรงนี้"**
- Drop Finder เรียงผลตาม **"เวลาที่คุณต้องใช้จริงกว่าจะได้ของชิ้นนี้"** ไม่ใช่แค่ % ดรอป
- หน้าแรกกลายเป็น "วันนี้ควรไปไหน" ที่ตอบเฉพาะตัว

**นี่คือสิ่งที่เว็บซึ่งทำเครื่องมือแยกเป็นเกาะไล่ตามได้ยาก** — ไม่ใช่ฟีเจอร์เดียว แต่เป็นชั้นที่ทุกฟีเจอร์อ่านร่วมกัน
**ต้อง handle:** localStorage ใช้ไม่ได้ (private mode) → ทุกหน้ายังต้องทำงานได้ตามปกติ แค่ไม่มีค่าเฉพาะตัว

### 3.15.3 คิด kills/hour ให้ แทนที่จะถาม

เรามี HP ของมอนทุกตัวอยู่แล้ว → ผู้ใช้กรอกดาเมจต่อครั้ง + ความเร็วโจมตี แล้วเราคำนวณเองทั้งหมด

**สูตร** (`lib/kills-per-hour.ts` — pure function เทสต์ได้):
```
hitsToKill   = ceil(monsterHp / damagePerHit)
secondsToKill = hitsToKill / attacksPerSecond
killsPerHour = 3600 / secondsToKill
expPerHour   = killsPerHour × monster.base_exp
```

**⛔ ข้อจำกัดที่ต้องบอกผู้ใช้ตรงๆ บนหน้า ห้ามซ่อน:** สูตรนี้คิด**เฉพาะเวลาที่ตีอยู่** ไม่รวมเวลาเดินหามอน เวลารอเกิดใหม่ และเวลาที่พลาด — **ตัวเลขจริงจะต่ำกว่านี้เสมอ** ให้ป้ายกำกับว่า *"เพดานบน ถ้ามีมอนให้ตีตลอดเวลา"* ไม่ใช่ *"EXP ต่อชั่วโมงที่จะได้"*

**ทำไมไม่ใส่ตัวคูณชดเชย:** เราไม่มีข้อมูลอัตราการเกิดใหม่หรือความหนาแน่นของมอนต่อแมพ การคูณ 0.7 ลอยๆ คือการเดาที่ดูเหมือนแม่นยำ ซึ่งแย่กว่าการบอกตรงๆ ว่านี่คือเพดานบน

**ตัวเลขตรวจสอบตอนเขียนเทสต์:** EXP/HP เฉลี่ยทั้งเซิร์ฟ ~0.6 (§3.9) → มอนที่ HP 1,000 ควรให้ราว 600 EXP ถ้าผลที่ออกมาผิดจากนี้เป็นสิบเท่าแปลว่าสูตรหรือหน่วยผิด

## 3.16 ตารางอัตราตีบวก — ข้อมูลอ้างอิง ไม่ใช่ฟีเจอร์ (26 ส.ค.)

`docs/refine-rates-reference.md` มีตารางเต็ม +1 ถึง +20 แยกตาม Armor / Weapon Lv.1–4 แล้ว **แต่ยังไม่ทำ Refine Simulator และไม่เอาตารางขึ้นหน้าเว็บสาธารณะ** — ใช้สองทางนี้แทน:
1. **ชุดตรวจสอบ** เมื่อวันหนึ่งอ่านค่าจากไฟล์เกมได้เอง เอามาเทียบ ถ้าตรงแสดงว่าอ่านถูก
2. **วัตถุดิบเขียนไกด์** โดยเฉพาะประเด็นที่ผู้เล่นเข้าใจผิดกันอยู่

**ข้อค้นพบที่ไม่มีคลิปไหนพูดถึงเลย:** **อัตราตีบวกใน Zero ขึ้นกับประเภทและระดับของ ไม่ใช่ตัวเลขชุดเดียวทั้งเกม** — Armor กับ Weapon Lv.4 ใช้ตารางเดียวกัน (ยากสุด) ส่วน Weapon Lv.1–2 ง่ายกว่ามาก (+11 ถึง +20 ยังอยู่ 15–18% ขณะที่เกราะเหลือ 5–8%)

→ **ปิดข้อขัดแย้งที่ §3.9 ค้างไว้:** NCZ กับ Viva-Tz **พูดถูกทั้งคู่ คนละสาย** · และค่าที่ user ทดสอบเอง (+1..+4 = 90%) ตรงกับสาย Weapon Lv.1–3

**ยังไม่รู้:** จำนวนแร่ต่อการตีหนึ่งครั้ง — เว็บทางการ `roz.mygnjoy.com` ที่น่าจะมีคำตอบ robots.txt ระบุ `User-agent: ClaudeBot / Disallow: /` เหลือสองทางคือไฟล์เกม หรือ user เปิดหน้าตีบวกในเกมแล้วดูว่ากินแร่กี่ก้อน · **ห้ามเดาว่า "RO ภาคอื่นกินก้อนเดียว Zero ก็คงเหมือนกัน"** — Zero ดัดแปลงกลไกหลายจุดแล้ว (อัตราตีบวกแยกตามระดับของ ซึ่งไม่มีในภาคอื่น คือตัวอย่างที่ชัดที่สุด) การเดาแบบนี้คือรูปแบบเดียวกับที่ทำให้ค่า renewal ของ rAthena ใช้กับ Zero ไม่ได้

## 4. สถาปัตยกรรม

ต่อยอดของเดิมทั้งหมด ไม่รื้อโครง:

**การเปลี่ยนแปลงฐานข้อมูล** (แก้ 26 ส.ค. — เดิมเขียนว่า "ไม่มีตารางใหม่" ซึ่งขัดกับ §3.7):
- `items` เพิ่ม 1 คอลัมน์: `description` (§3.0)
- `monsters` เพิ่ม: `is_aggressive`, `is_mvp`, `loots_items`, `matk_min`, `matk_max`, `str`, `agi`, `vit`, `int_`, `dex`, `luk` (§3.7)
- **ตารางใหม่ 1 ตาราง:** `monster_skills` (§3.7)
- ทุก migration เป็น `alter table ... add column` + `create table if not exists` — import เป็น upsert ทับของเดิม **ไม่ล้างตาราง** (ข้อมูลเดิมต้องไม่หาย)
- **RLS ต้องเปิดกับตารางใหม่ด้วย** — v1 เคยพลาดจนคีย์ anon ลบข้อมูลได้ ตารางใหม่ต้องมี policy อ่านอย่างเดียวตั้งแต่ migration แรก

**ชั้นใหม่ฝั่งหน้าเว็บ:**
- `lib/character-context.ts` — อ่าน/เขียนบริบทตัวละครใน localStorage + hook สำหรับ client component (§3.15.2) · **ต้องเป็น pure function ที่เทสต์ได้** แยกจากตัว hook
- `components/AggroBadge.tsx` — ธง active-attack ใช้ซ้ำทุกที่ (§3.15.1)
- `lib/kills-per-hour.ts` — pure function คำนวณเวลาต่อคิล (§3.15.3)

**คงแพทเทิร์นเดิม:**
- หน้าใหม่ทุกหน้า: server component query Supabase → filter/pagination ผ่าน GET query params (ทำงานได้โดยไม่ต้องมี JS, bookmark ได้) → `revalidate = 86400` สำหรับหน้า list
- **ข้อยกเว้น:** ส่วนที่อ่านบริบทตัวละครต้องเป็น client component เพราะ localStorage อ่านบนเซิร์ฟเวอร์ไม่ได้ → **ให้หน้าเป็น server component เหมือนเดิม แล้วห่อเฉพาะส่วนที่ต้องใช้บริบทเป็น client component ย่อย** ไม่เปลี่ยนทั้งหน้าเป็น client (จะเสีย SEO ซึ่งขัดกับ §3.13)
- **Reuse:** `components/Pagination.tsx`, CSS ใน `globals.css`, error handling เดิม (`console.error` + empty state ไม่ crash)
- **⚠️ ตาราง `products` ของโปรเจกต์อื่นเคยพลาดเพราะ Supabase คืนแค่ 1,000 แถวเงียบๆ** — `items` มี 1,300 แถว **เกินเพดานแล้ว** ทุก query ที่ตั้งใจดึงทั้งตาราง (เช่นตอน import, ตอนทำ sitemap) ต้องวนดึงเป็นชุด ไม่ใช่ `select()` รวดเดียว

ตาม spec เดิม (§6 ของ v1) — unit test เฉพาะ pure function, UI ตรวจด้วยมือผ่าน dev server + browser จริง · ไม่ทำ E2E อัตโนมัติ

**pure function ที่ต้องมีเทสต์:**

| ไฟล์ | เทสต์อะไร | เคสที่ห้ามลืม |
|---|---|---|
| `lib/parse-item-text.ts` (มีแล้ว) | parse `Equipped on :` จาก description | description เป็น null, บรรทัดไม่มี `Equipped on` |
| `lib/elements.ts` | ตัวคูณธาตุ | คู่ที่รู้คำตอบล่วงหน้า + ธาตุที่ไม่มีในตาราง |

| `lib/kills-per-hour.ts` | สูตร §3.15.3 | ดาเมจ 0 (ห้ามหารด้วยศูนย์) · ดาเมจมากกว่า HP (ต้องได้ 1 ฮิต ไม่ใช่ 0) · HP เป็น 0 |
| `lib/aggro-tier.ts` | เกณฑ์ §3.15.1 | **ไม่มีบริบท → ต้องคืน 2 ระดับ ไม่ใช่ 3** · `atk_max` เป็น null |
| `lib/farm-planner.ts` | สรุปผลรวม | แผนว่าง · มอนซ้ำ |

**เกณฑ์ที่บังคับกับทุกเทสต์ในรอบนี้:** เขียนเทสต์แล้วต้อง**พิสูจน์ว่ามันแดงได้จริง** — ลบหรือกลับตรรกะที่มันอ้างว่าตรวจ แล้วดูว่าเทสต์แดง ถ้าเขียวอยู่แสดงว่าเทสต์นั้นไม่ได้ตรวจอะไร

**ตรวจด้วยมือก่อน deploy (ทำจริง ไม่ใช่อ่านโค้ดแล้วเดา):**
1. เปิดเว็บใน private window — ทุกหน้าต้องเปิดได้ ไม่ crash แม้ localStorage ใช้ไม่ได้
2. หน้าสกิล — **ไอคอนต้องขึ้นจริง** ไม่ใช่กรอบว่าง (บทเรียนจาก PCX Hub: รูปพังแบบไม่ error)
3. มือถือ 340px — EXP/HP ต้องมองเห็นโดยไม่ต้องเลื่อนข้าง (§6.4)
4. หน้ามอนสเตอร์ที่ `atk_max` เป็น null — ต้องไม่ขึ้น `NaN` หรือป้ายเพี้ยน

**ข้อยกเว้นเดียว — ธง active-attack (§3.15.1)** ต้องใช้สีบอกสถานะซึ่งไม่มีใน token ชุดเดิม:
- ปลอดภัย = เขียว · ระวัง = เหลือง (`#FFE53D` ที่มีอยู่แล้ว) · อันตราย = แดง
- **ห้ามใช้สีอย่างเดียว** ต้องมีไอคอนหรือข้อความกำกับด้วย — คนตาบอดสีต้องแยกออก และป้ายนี้คือจุดต่างหลักของเว็บ ถ้าอ่านไม่ออกก็เสียของ
- เขียว/แดงเป็นสีสถานะ **ไม่ใช่ accent ใหม่ของระบบดีไซน์** ห้ามเอาไปใช้ตกแต่งที่อื่น
### 6.1 เมนู — เลือกแบบสองชั้น (ตัดสินใจแล้ว 26 ส.ค.)

เมนูจะโตจาก 4 เป็น 10 รายการ เทียบ 4 แบบเป็นภาพจริงแล้ว ([artifact](https://claude.ai/code/artifact/789fb9a7-de0c-4ab7-9ad6-5429935243cf)) — **เลือกแบบ C สองชั้น**

- **แถวบน (คงที่):** `หาจุดตี` · `ค้นของดรอป` · `ฐานข้อมูล` · `เครื่องมือ` + ช่องค้นหา
  - ของที่คนใช้บ่อยสุด (หาจุดตี, ค้นของดรอป) กดครั้งเดียวถึง ไม่ต้องกดซ้อน
- **แถวล่าง (เปลี่ยนตามหมวดที่อยู่):**
  - หมวดฐานข้อมูล → มอนสเตอร์ · ไอเทม · การ์ด · อุปกรณ์ · สกิล · แมพ (แสดงจำนวนต่อท้ายบนจอคอม)
  - หมวดเครื่องมือ → ตารางธาตุ · แผนฟาร์ม
  - หน้าที่ไม่อยู่ในหมวดไหน (หาจุดตี, ค้นของดรอป) → ไม่มีแถวล่าง
- **มือถือ:** แถวบนยุบเป็นปุ่ม ☰ + ช่องค้นหาคาไว้เสมอ, แถวล่างเลื่อนข้างได้ (มีแค่หมวดเดียวจึงไม่เกะกะ)
- **ต้องผูก route → หมวด ในโค้ด** (เช่น `/database/*` = หมวดฐานข้อมูล, `/tools/*` = หมวดเครื่องมือ)

**ทำไมไม่เลือกแบบอื่น:** A (เรียงยาว) มือถือใช้ไม่ได้จริง · B (dropdown แบบ midgardhub) บังคับกด 2 ครั้งกับหน้าที่ใช้บ่อยสุด · D (ค้นหานำ) เก็บไว้ทีหลัง — **ยังทำไม่ได้ตอนนี้เพราะ Global Search ค้นได้แค่มอนสเตอร์กับไอเทม** ถ้าดันค้นหาเป็นพระเอกทั้งที่ค้นการ์ด/สกิล/แมพไม่ได้ คนพิมพ์แล้วไม่เจอจะเลิกเชื่อ → **ต้องขยาย Global Search ให้ครบ 6 อย่างก่อน ถึงจะย้ายไป D ได้**

### 6.2 หน้าแรก — เลือกแบบผสม (ตัดสินใจแล้ว 26 ส.ค.)

เทียบ 4 แบบเป็นภาพจริงแล้ว ([artifact](https://claude.ai/code/artifact/521731eb-6370-4d1c-a2e7-43bb6f5158bb)) — **เลือกแบบผสม** คือ `/` ยังเป็น Farming Finder เหมือนเดิม แต่เพิ่มบริบทรอบๆ

โครงหน้าแรกใหม่ เรียงจากบนลงล่าง:
1. H1 เดิม (`หามอนสเตอร์คุ้มสุด สำหรับเลเวลของแก`)
2. **บรรทัดใหม่:** คำโปรยสั้นบอกว่านี่เป็นส่วนหนึ่งของฐานข้อมูล Ragnarok Zero ภาษาไทย
3. **แถบตัวเลขใหม่:** มอนสเตอร์ 524 · ไอเทม 1,300 · การ์ด 289 · อุปกรณ์ 490 · สกิล 851 · แมพ 497 — **ดึงสดจาก DB ไม่ hardcode** (ข้อมูลเพิ่มแล้วตัวเลขต้องขยับเอง) แต่ละตัวลิงก์ไปหน้านั้น
4. ฟอร์มค้นเลเวล + ตารางผลลัพธ์ (เดิม ไม่แตะ)
5. **ท้ายหน้าใหม่:** การ์ดทางเข้า 4 ใบ (ค้นของดรอป, ตารางธาตุ, การ์ด, แมพ) — คุมไม่ให้เกิน 4-6 ใบ ไม่งั้นหน้าบวม

**ข้อดีที่ทำให้เลือกแบบนี้:** ไม่ต้องย้าย URL — ลิงก์ที่จะแชร์ในกลุ่มเกมยังเป็น `/` เหมือนเดิม ไม่ต้องทำ redirect และคนกลับมาใช้ซ้ำไม่ต้องคลิกเพิ่ม

**ไม่เลือกแบบหน้ารวมทางเข้า** เพราะต้องย้าย Farming Finder ไป URL ใหม่ + คนใช้ซ้ำต้องคลิกเพิ่มทุกครั้ง
**ไม่เลือกแบบค้นหาเป็นพระเอก** ด้วยเหตุผลเดียวกับเมนูแบบ D — Global Search ยังครอบคลุมแค่ 2 ใน 6

### 6.3 ขยาย Global Search ให้ครบ 6 อย่าง

ปัจจุบันค้นได้แค่ `monsters` + `items` → ต้องเพิ่ม **การ์ด, อุปกรณ์, สกิล, แมพ** เข้าไปด้วย

- `mergeSearchResults` ปัจจุบันรับ 2 พารามิเตอร์ (monsters, items) — ต้องเปลี่ยนเป็นรับหลายกลุ่ม พร้อม badge สีต่อประเภท
- การ์ด/อุปกรณ์เป็น subset ของ `items` (filter ด้วย category) → ต้องแยก badge ให้ผู้ใช้เห็นว่าเป็นการ์ด ไม่ใช่ไอเทมทั่วไป
- แมพค้นจาก `monster_spawns.map_display_name` / `map_code`
- **ปลดล็อกอนาคต:** เมื่อค้นครบ 6 อย่างแล้ว จะย้ายเมนูไปแบบ D และหน้าแรกไปแบบค้นหานำได้ (ทั้งสองอย่างติดเงื่อนไขนี้เหมือนกัน)

### 6.4 หน้ารายการทั้ง 6 หน้า — ตารางเหมือนกันหมด + มือถือเป็นแถวการ์ด (ตัดสินใจแล้ว 26 ส.ค.)

เทียบเป็นภาพจริงแล้ว ([artifact](https://claude.ai/code/artifact/4e754ec5-dff9-4bd8-b09a-e5e5e97ed73b))

**จอคอม — ตารางทั้ง 6 หน้า** (มอนสเตอร์ ไอเทม การ์ด อุปกรณ์ สกิล แมพ) ไม่ทำกริดแยกให้การ์ด/อุปกรณ์
- ตรวจข้อมูลจริงแล้ว: เอฟเฟกต์การ์ดส่วนใหญ่สั้นบรรทัดเดียว (`ATK +20`, `LUK +2, Perfect Dodge +1`) → ปัญหาแถวเบี้ยวที่กลัวไว้ไม่เกิดจริง
- วิธีใช้จริงของหน้าการ์ดคือกวาดหา "การ์ดที่เพิ่ม X" ซึ่งคอลัมน์เดียวเรียงกันเทียบเร็วกว่ากริด
- **ได้เปรียบสำคัญ:** เขียน component เดียวใช้ซ้ำ 6 หน้า ไม่ต้องดูแลสองรูปแบบ

**มือถือ — เปลี่ยนตารางเป็นแถวการ์ด** (ไม่ใช่เลื่อนข้างแบบปัจจุบัน)
- **ปัญหาจริงที่ค้นพบ:** ตารางปัจจุบันบนมือถือ 340px ทำให้ **EXP/HP (คอลัมน์ที่ 4) หลุดออกนอกจอ** — คือค่าที่เป็นหัวใจของ Farming Finder ทั้งหน้า มองไม่เห็นเลยจนกว่าจะเลื่อน ซึ่งคนส่วนใหญ่ไม่ทำ · กลุ่มเป้าหมายหลักคือคนเล่นเกมมือถือ = ปัญหานี้กระทบคนส่วนใหญ่
- แต่ละแถวแสดง: ไอคอน + ชื่อ + ค่าสำคัญทั้งหมดเรียงเป็น meta 2 บรรทัด (ไม่มีอะไรซ่อน)
- **ทำด้วย CSS ล้วน** — ตาราง HTML เดียวกัน เปลี่ยนการแสดงผลตาม breakpoint ไม่ต้องเขียน component แยกหรือ render สองชุด

### 6.5 หน้ารายละเอียดมอนสเตอร์ — สองคอลัมน์ (ตัดสินใจแล้ว 26 ส.ค.)

หน้านี้โตจากโชว์ 8 ค่าเป็น ~25 ค่า + สกิลมอน + จุดเกิด + ตารางธาตุ · เทียบ 3 แบบเป็นภาพจริงแล้ว ([artifact](https://claude.ai/code/artifact/bb7fc2d7-30bd-473b-a675-f0e0967b6a8d)) — **เลือกสองคอลัมน์บนจอคอม ยุบเป็นคอลัมน์เดียวบนมือถือ**

**ลำดับเนื้อหา** (เรียงตามสิ่งที่คนเข้ามาหาจริง):
1. หัวเรื่อง: รูป + ชื่อ + Lv/เผ่า/ธาตุ+ระดับ/ขนาด + **ป้ายสถานะ**
2. แถบรางวัล: Base EXP · Job EXP · EXP/HP · Zeny/ตัว
3. สองคอลัมน์ — ซ้าย: ค่าสถานะ (HP/ATK/MATK/DEF/MDEF/FLEE/HIT + STR-LUK) และตารางธาตุ · ขวา: ตารางดรอป, จุดเกิด, สกิลที่มอนใช้
4. ปุ่มแจ้งข้อมูลผิด

**⛔ ห้ามใช้แท็บ** — หน้ามอนสเตอร์มี 524 หน้า เป็นตัวหลักที่ดึงคนจาก Google (ตรงกับเป้าหมายหาคนเข้าเว็บ) เนื้อหาที่ซ่อนในแท็บที่ไม่ได้เปิดได้คะแนน SEO น้อยกว่ามาก และ Ctrl+F หาไม่เจอ

**3 จุดที่ต้องทำให้ถูก:**
1. **ป้าย "⚠ ตีเราก่อน" (Aggressive) ต้องเด่นที่สุดในหน้า** — เอกสาร YouTube ระบุว่าเป็นข้อมูลที่คนหาที่ AFK ต้องการมากที่สุด และ**ไม่มีเว็บคู่แข่งเจ้าไหนแสดง** = จุดต่างที่ชัดที่สุดของเรา
2. จุดเกิดต้อง**ลิงก์ไปหน้าแมพ** เพื่อให้เดินต่อไปดู "แมพนี้มีมออะไรอีก"
3. **Zeny/ตัว ต้องมี tooltip** อธิบายว่าคำนวณจาก ราคาขาย × อัตราดรอป ไม่ใช่เงินที่มอนดรอปตรงๆ (ไม่งั้นผู้ใช้เข้าใจผิด)
