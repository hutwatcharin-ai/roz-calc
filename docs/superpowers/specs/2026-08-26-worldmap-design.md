# ROZ Calc — หน้าแผนที่โลก (World Map)

**สถานะ:** ร่าง รอ user รีวิว
**เกี่ยวข้อง:** `2026-08-26-roz-calc-v2-design.md` (v2) — หน้านี้เป็นงานแยก ไม่อยู่ในคลื่น 2A หรือ 2B
**เว็บอ้างอิง:** `rozerodb.com/maps` (สำรวจ 26 ส.ค. 69)

---

## 1. เป้าหมายและขอบเขต

หน้าแผนที่โลกแบบโต้ตอบได้ ใช้ภาพแผนที่ในเกม ผู้เล่นกดที่จุดใดจุดหนึ่งแล้วเห็นว่าที่นั่นมีอะไร ระดับไหน อันตรายแค่ไหน

**สิ่งที่หน้านี้ไม่ใช่:** ดัชนีแมพ หน้า `/database/maps` ยังเป็นดัชนีจริงและครบทั้ง 497 แมพ แผนที่โลกเป็นทางเข้าสำหรับที่ที่ผู้เล่นรู้จักชื่ออยู่แล้ว ทั้งสองหน้าอยู่ด้วยกันและลิงก์หากัน

**เหตุผลที่ต้องแยกให้ชัด** — สำรวจเว็บอ้างอิงแล้วพบว่าแผนที่ของเขาปักหมุดครอบคลุม **99 รหัสแมพ** ซึ่งกินสัดส่วนแค่ **17% ของ spawn ทั้งหมด (515 จาก 3,032 แถว)** และ **417 แมพในฐานข้อมูลเราไม่มีหมุดเลย** ถ้าพยายามปักให้ครบ 497 หมุดจะทับกันจนกดไม่ได้ นี่ไม่ใช่ข้อจำกัดของเขา แต่เป็นธรรมชาติของรูปแผนที่ขนาด 1280×1024

## 2. ผลสำรวจเว็บอ้างอิง

สำรวจ `rozerodb.com/maps` ด้วย curl โดยไม่รัน JS — หน้าเป็น server-rendered ทั้งหมด `robots.txt` ของเขาคือ `Allow: /` + `Disallow: /api/` การเปิดอ่านหน้าเว็บไม่ถูกห้าม

### โครงสร้างที่เขาใช้

| ส่วน | รายละเอียดที่ตรวจพบ |
|---|---|
| ภาพ | `/assets/maps/worldmap_z.jpg` — 1280×1024 JPEG, alt "Orbis of Midgard world map" |
| viewport | `worldMapViewport` / `worldMapStage` / `worldMapWorkspace` — pan/zoom |
| ปุ่มควบคุม | `+` / `−` / `RESET` ใน `worldMapControls` |
| หมุดโซน | `wmZone` **89 อัน** พิกัด px ตายตัว เช่น `left:976px;top:639px;width:94px;height:34px` |
| หมุดถ้ำพิเศษ | `worldMapDungeonMarker` 2 อัน |
| หมุด Kafra | `worldMapKafraClickTargetV19B` **9 อัน** มี `title="Kafra Teleport — <เมือง>"` |
| ค้นหา | `worldMapSearch` — placeholder "Search a map, region or monster" |
| แผงข้าง | `worldMapPanel` พร้อมสถานะ `worldMapEmpty` และ `worldMapHint` |

### ตัวเลขที่วัดได้

- หมุดโซน 89 อัน แต่มีเพียง **5 อัน** ที่ผูกหลายแมพ อีก 84 อันเป็นแมพเดี่ยว
- กลุ่มใหญ่สุดคือ `pay_dun00 / pay_dun01 / pay_dun02 / pay_dun03 / pay_dun04` (ถ้ำ Payon 5 ชั้น)
- รวมรหัสแมพที่ปักหมุด **99 รหัส**
- ในจำนวนนั้นฐานข้อมูลเรามี **80 รหัส** อีก 19 เป็นเมืองและสนามกิลด์ที่ไม่มีมอนเกิด จึงไม่มีในข้อมูลเรา (`prontera`, `geffen`, `aldebaran`, `prt_mk_g1`, `alde_gld` ฯลฯ)
- เมือง Kafra 9 แห่ง: Prontera, Geffen, Payon, Morroc, Alberta, Aldebaran, Comodo, Izlude, Umbala

### สามอย่างที่เขาทำถูกและควรลอกโครง

1. **pan/zoom พร้อมปุ่ม RESET** — ภาพ 1280×1024 บนจอมือถือ 360px ถ้าไม่มีสิ่งนี้คือใช้ไม่ได้เลย ไม่ใช่ลูกเล่น
2. **หมุดหนึ่งอันผูกได้หลายแมพ** — โครงข้อมูลรองรับไว้ แม้เขาจะใช้จริงแค่ 5 อัน
3. **หมุด Kafra แยกชนิด** — เป็นกลไกจริงในเกมที่ตรวจสอบได้ และมีแค่ 9 จุด ไม่ต้องเดาอะไรเลย

### ช่องว่างที่เห็นชัด

- **แผนที่ตอบได้แค่ "ที่นี่อยู่ตรงไหน" ไม่ตอบ "เลเวลนี้ควรไปไหน"** หมุดไม่มีเลเวลมอน ไม่มี EXP ไม่มีข้อมูลว่ามอนเข้าตีเองไหม
- 417 แมพเข้าถึงจากแผนที่ไม่ได้เลย และหน้าแผนที่ไม่ได้บอกผู้ใช้ว่ายังมีแมพอื่นอีก
- ช่องค้นหาแยกจากแผนที่ พิมพ์แล้วต้องกวาดตาหาเองว่าหมุดไหนตอบสนอง

**นี่คือจุดที่เราได้เปรียบ** — ข้อมูลที่หมุดของเราจะแสดงได้ เรามีอยู่ในฐานข้อมูลแล้วทั้งหมด

## 3. เรื่องภาพแผนที่ — บันทึกการตัดสินใจ

**ใช้ภาพแผนที่ในเกม** ตามที่ user ตัดสิน ไฟล์เก็บที่ `public/images/maps/worldmap.jpg` (1280×1024 JPEG, 483,747 ไบต์)

ตรวจไฟล์แล้วเป็นภาพ "Orbis of Midgard" ของเกมพร้อมเส้นกริดจาก client ไม่มีลายน้ำ ไม่มีเครื่องหมายของ rozerodb — เป็นทรัพยากรของเกมที่เว็บฐานข้อมูล RO ใช้กันทั่วไป ไม่ใช่งานที่ rozerodb สร้างขึ้นเอง

**ความเสี่ยงที่บันทึกไว้:** เป็นงานศิลป์ของ Gravity user ทราบและตัดสินใจแล้ว บันทึกไว้ที่นี่เพื่อให้อยู่ในบันทึกโครงการ ไม่ใช่เพื่อทบทวนใหม่

**สิ่งที่ไม่เอา: พิกัดหมุด 89 อันของ rozerodb** เป็นงานที่เขานั่งวางเอง และที่สำคัญกว่านั้นคือ**เราไม่ควรอยากได้** เพราะการจัดกลุ่มของเขาไม่ตรงกับที่เราต้องการ — เขาแยกถ้ำเป็นหมุดเดี่ยว 84 จาก 89 อัน ส่วนเราต้องการหมุดเดียวครอบทุกชั้น (ดู §5)

## 4. สถาปัตยกรรมข้อมูล

### 4.1 ตารางใหม่ `map_regions`

```sql
create table map_regions (
  slug text primary key,              -- 'payon-cave'
  name_en text not null,              -- 'Payon Cave'
  name_th text,                       -- 'ถ้ำพะยอน'
  kind text not null,                 -- 'city' | 'dungeon' | 'field' | 'special'
  x integer not null,                 -- ตำแหน่งบนภาพ 1280x1024
  y integer not null,
  width integer not null,
  height integer not null,
  has_kafra boolean not null default false,
  sort_order integer not null default 0
);

create table map_region_maps (
  region_slug text not null references map_regions (slug) on delete cascade,
  map_code text not null,
  primary key (region_slug, map_code)
);
```

**ทำไมแยกสองตาราง:** หมุดหนึ่งอันผูกหลายแมพ (ถ้ำ 5 ชั้น = หมุดเดียว) ถ้าเก็บเป็น array ในตารางเดียวจะ join กับ `map_stats` ไม่ได้ และเป็นบทเรียนตรงจากตาราง `monster_skills` ที่ primary key ผิดแล้วทิ้งข้อมูลจริง 28%

**RLS ต้องอยู่ใน migration เดียวกับที่สร้างตาราง** — public `select` เท่านั้น ไม่มี policy เขียน v1 เคยพลาดจนคีย์ anon ลบข้อมูลได้

**`map_code` ไม่มี foreign key ไปไหน** โดยตั้งใจ — เมืองอย่าง `prontera` และ `geffen` ไม่มีมอนเกิด จึงไม่อยู่ใน `map_stats` แต่ต้องปักหมุดได้ ถ้าผูก FK จะปักเมืองไม่ได้เลย

### 4.2 view `map_region_stats`

รวมสถิติต่อหมุด เพื่อไม่ต้องคำนวณตอน render:

```sql
create or replace view map_region_stats as
select
  r.slug,
  r.name_en,
  r.name_th,
  r.kind,
  r.x, r.y, r.width, r.height,
  r.has_kafra,
  count(distinct rm.map_code) as map_count,
  coalesce(sum(ms.monster_count), 0)::integer as spawn_count,
  min(m.level) as min_level,
  max(m.level) as max_level,
  count(distinct m.id) filter (where m.is_aggressive) as aggressive_count
from map_regions r
left join map_region_maps rm on rm.region_slug = r.slug
left join map_stats ms on ms.map_code = rm.map_code
left join monster_spawns s on s.map_code = rm.map_code
left join monsters m on m.id = s.monster_id
group by r.slug, r.name_en, r.name_th, r.kind, r.x, r.y, r.width, r.height, r.has_kafra;

alter view map_region_stats set (security_invoker = on);
```

`left join` ทุกจุด เพราะหมุดเมืองไม่มีมอนเลย ต้องยังคืนแถวพร้อมค่าศูนย์ ไม่ใช่หายไป

⚠️ **`min_level` / `max_level` เป็น null ได้** เมื่อหมุดไม่มีมอน — ต้องแสดง `—` ไม่ใช่ `0`

## 5. สิ่งที่หมุดของเราแสดง และเขาแสดงไม่ได้

หมุดของ rozerodb บอกได้แค่รายชื่อรหัสแมพใน `title` ของเรามีข้อมูลอยู่แล้ว:

> **Payon Cave** · 5 ชั้น · มอน Lv.15–40 · 47 ตัว · ⚠ เข้าตีเอง 3 ชนิด

ทุกค่ามาจาก `map_region_stats` ตรงๆ ไม่มีอะไรต้องคำนวณสด ไม่มีอะไรต้องเดา

**การจัดกลุ่มต่างจากเขาโดยตั้งใจ** — ถ้ำหลายชั้นเป็นหมุดเดียว ไม่ใช่หมุดซ้อนกัน 5 อัน เพราะคำถามของผู้เล่นคือ "ถ้ำพะยอนคุ้มไหม" ไม่ใช่ "ชั้น 3 อยู่ตรงไหนบนแผนที่" เมื่อกดแล้วแผงข้างค่อยแตกเป็นรายชั้นพร้อมเลเวลของแต่ละชั้น

## 6. เครื่องมือวางหมุด — ส่วนที่ทำให้งานนี้เป็นไปได้

**ปัญหา:** ต้องได้พิกัด ~90 หมุดบนภาพ 1280×1024 การเดาพิกัดแล้วแก้ทีละรอบคือทางที่พังแน่นอน

**ทางแก้: สร้างหน้าเครื่องมือภายในหนึ่งหน้า** `/admin/map-placer` (ไม่อยู่ใน sitemap ไม่มีลิงก์จากที่ไหน)

- แสดงภาพแผนที่ขนาดจริง
- คลิกลากเพื่อวาดกล่อง แล้วกรอกชื่อกับรหัสแมพที่ผูก
- หมุดที่วางแล้วแสดงทับบนภาพ กดแก้หรือลบได้
- ปุ่มเดียว: คัดลอก JSON ของหมุดทั้งหมด
- JSON นั้นกลายเป็น seed ของ `map_regions` — commit ลง repo เป็นไฟล์ข้อมูล ไม่ใช่ migration ที่มี INSERT ยาวเหยียด

**ทำไมคุ้มสร้าง:** เปลี่ยนงานเดาพิกัดหลายชั่วโมงให้เป็นงานคลิกที่ตรวจสอบด้วยตาได้ทันที และเมื่อเพิ่มหมุดในอนาคตต้นทุนแทบเป็นศูนย์ นี่คือส่วนที่ทำให้ "ทำให้ดี" เป็นไปได้จริงแทนที่จะเป็นความตั้งใจ

### 7.1 โครง

```
┌──────────────────────────────────────────────────────┐
│  แผนที่โลก            [ค้นหาแมพ มอน หรือเขต    ]     │
├────────────────────────────────┬─────────────────────┤
│                                │  Payon Cave         │
│    ภาพแผนที่ + หมุด             │  ถ้ำพะยอน            │
│    (pan / zoom)                │  ─────────────      │
│                                │  5 ชั้น              │
│         [+] [−] [RESET]        │  Lv.15–40           │
│                                │  47 ตัว              │
│                                │  ⚠ เข้าตีเอง 3       │
│                                │  ─────────────      │
│                                │  ชั้น 1  Lv.15-20 →  │
│                                │  ชั้น 2  Lv.18-25 →  │
└────────────────────────────────┴─────────────────────┘
   497 แมพทั้งหมดในเกม ดูรายการเต็มที่ ฐานข้อมูลแมพ →
```

บรรทัดล่างสุดสำคัญ — บอกตรงๆ ว่าแผนที่ไม่ครบ และชี้ไปที่ที่ครบ

### 7.2 การโต้ตอบ

- คลิกหมุด → แผงข้างแสดงรายละเอียด URL เปลี่ยนเป็น `?region=payon-cave` (แชร์ลิงก์ได้ กดย้อนกลับได้)
- คลิกชั้นในแผง → ไปหน้า `/database/maps/[code]` ที่มีอยู่แล้ว
- คลิกหมุด Kafra → แผงบอกว่าเทเลพอร์ตจากเมืองนี้ไปไหนได้บ้าง
- คลิกที่ว่าง → ปิดแผง
- ค้นหา → หมุดที่ตรงเรืองแสง หมุดอื่นจาง และ**เลื่อนภาพไปหาหมุดแรกที่ตรงให้อัตโนมัติ** (สิ่งที่เว็บอ้างอิงไม่ทำ)

### 7.3 มือถือ

ภาพ 1280×1024 บนจอ 360px ต้องออกแบบเฉพาะ ไม่ใช่ย่อส่วน:

- เริ่มที่ระดับซูมพอดีความกว้างจอ ลากสองนิ้วเพื่อซูม
- แผงข้างกลายเป็น bottom sheet
- **หมุดต้องมีพื้นที่กดอย่างน้อย 44×44px** ต่อให้กล่องจริงเล็กกว่านั้น — หมุดของเว็บอ้างอิงบางอันสูง 21px ซึ่งกดพลาดบนมือถือ
- ปุ่ม RESET ต้องเข้าถึงได้เสมอ

### 7.4 การเข้าถึง

- หมุดทุกอันเป็น `<button>` โฟกัสด้วยคีย์บอร์ดได้ ไล่ตามลำดับที่อ่านเข้าใจ (เมืองก่อน แล้วถ้ำ)
- `aria-label` บอกชื่อเขตและจำนวนแมพ ไม่ใช่แค่รหัส
- ธง "เข้าตีเอง" ต้องมีข้อความหรือไอคอนกำกับ ไม่พึ่งสีอย่างเดียว — กฎเดียวกับที่ระบบใช้อยู่แล้ว
- ต้องมีทางไปถึงข้อมูลเดียวกันโดยไม่ต้องใช้แผนที่ ซึ่งคือหน้า `/database/maps` ที่มีอยู่แล้ว

## 8. เส้นทางเชื่อมระหว่างแมพ — ยังไม่ทำ

**ตรวจแล้วว่ามีข้อมูล แต่ยังไม่พอ**

rAthena (GPL-3.0 เปิดจริง) มีไฟล์ warp ที่ให้ทั้งเส้นเชื่อมและพิกัดจุดวาร์ป:

```
payon,122,27,0	warp	payonwarp003	5,3,pay_fild01,333,356
```

ดึงมาแล้ว 79 ไฟล์ → **1,864 เส้น / 329 แมพ** แต่ทับกับ 497 แมพของเราแค่ **27%** เพราะรหัสแมพของ Zero ถูกแปลงจากคลาสสิก ทดสอบแล้วมีกฎเป็นระบบ (`gef_f10_a` → `gef_fild10`, `pay_d04_a` → `pay_dun04`) ใส่กฎแล้วขึ้นเป็น **292/497 = 59%**

**เหตุผลที่ยังไม่ทำ:** 159 จาก 292 เส้นมาจาก**การอนุมาน**ว่าแมพ Zero มีผังเหมือนแมพคลาสสิกที่ชื่อคล้ายกัน Zero ดัดแปลงแมพจริง (ชื่อถึงได้ต่าง) การเอาผัง renewal มาแปะแล้วบอกว่าเป็นของ Zero คือความผิดพลาดแบบเดียวกับที่โปรเจกต์นี้ตัด rAthena ทิ้งตั้งแต่ v2 §2

**สิ่งที่ทำแทน: หมุด Kafra 9 เมือง** เป็นกลไกจริงที่ตรวจสอบได้ในเกม จำนวนน้อย และเป็นเส้นทางที่ผู้เล่นใช้จริงมากกว่าการเดินทะลุทุ่ง

เมื่อวันหนึ่งอ่านผังจากไฟล์เกมได้ ค่อยเพิ่มเส้นเชื่อม โดยเส้นที่มาจากการอนุมานต้องแสดงต่างจากเส้นที่ยืนยันแล้ว

ตามแนวเดิมของโปรเจกต์ — unit test เฉพาะ pure function ส่วน UI ตรวจด้วยมือในเบราว์เซอร์จริง

| ไฟล์ | เทสต์อะไร | เคสที่ห้ามลืม |
|---|---|---|
| `lib/map-regions.ts` | แปลงแถวจาก view เป็นข้อมูลหมุด | หมุดที่ไม่มีมอน (`min_level` null) · หมุดที่ผูกแมพที่ไม่มีใน `map_stats` |
| `lib/map-viewport.ts` | คณิตศาสตร์ pan/zoom | ซูมสุด/น้อยสุด · ลากเกินขอบภาพ · RESET กลับค่าเริ่มต้น |
| `lib/map-search.ts` | ค้นหาแล้วคืนหมุดที่ตรง | ค้นด้วยชื่อมอน · ค้นด้วยรหัสแมพ · ค้นแล้วไม่เจอ |

**บังคับ:** เขียนเทสต์แล้วต้องพิสูจน์ว่ามันแดงได้จริง — ลบตรรกะที่มันอ้างว่าตรวจแล้วดูว่าแดงไหม

**ตรวจด้วยมือก่อนปล่อย:**
1. มือถือ 360px — ซูมพอดีจอตอนเปิด กดหมุดที่เล็กที่สุดติด
2. หมุดเมือง (ไม่มีมอน) — แสดง `—` ไม่ใช่ `0`
3. `?region=payon-cave` เปิดตรงมาแล้วแผงเปิดอยู่
4. คีย์บอร์ดอย่างเดียว — ไล่ถึงทุกหมุดและเปิดแผงได้

**เฟส 1 — โครงที่ใช้งานได้จริง**

4. หน้าแผนที่: ภาพ + pan/zoom + RESET + หมุด + แผงข้าง
5. ค้นหา + เลื่อนหาหมุด

**เฟส 3 — เกินเว็บอ้างอิง**
