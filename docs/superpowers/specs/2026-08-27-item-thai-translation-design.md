## 1. ปัญหาและการตัดสินใจ

ตอนนี้เว็บเป็นภาษาไทยเฉพาะตัวเว็บ ส่วน**เนื้อหาเกมเป็นอังกฤษล้วน** — `items.description` 1,213 แถวไม่มีอักษรไทยแม้ตัวเดียว และ `items.name_th` กับ `monsters.name_th` ว่างทั้ง 1,300 และ 524 แถว ไม่มีโค้ดไหนอ่านสองคอลัมน์นั้นเลย

**ไม่มีแหล่งไทยให้ import** — ไฟล์ดิบมี `localizedNames` แค่ `zh_tw` กับ `kr` และ description ระบุที่มาว่า `client-iteminfo-enUS` เพราะ Ragnarok Zero Global เป็นเกมภาษาอังกฤษ ไม่มี client ไทย

### ทำไมไม่เอาคำแปลทางการจาก Divine-Pride

Divine-Pride มีคำแปลไทยจริงจากเซิร์ฟไทยทางการ (`thROC` / `thROG`) แต่**ตัดสินใจไม่ใช้** ด้วยสามเหตุผลที่ตรวจสอบแล้ว:

**1. เงื่อนไขของเขาห้ามตรงตัว** — บันทึกไว้ตั้งแต่ v2 §2: *"Don't try to mirror the whole database"* และ *"scripted bulk id enumeration... will get a key revoked"* การดึง 1,213 รายการคือสิ่งที่เขาห้าม

**2. เป็นคำแปลของเกมคนละเวอร์ชัน และตกข้อมูล** — เทียบ Baphomet Card (id 4147) แล้ว:

| ข้อมูลเรา | `Normal physical attacks (excluding skills) become 9-cell splash attacks.` + **`HIT -10.`** |
| thROG | `กระจายค่าความเสียหายจากการโจมตีเป็น 9 ช่อง จากการโจมตีของตัวละคร` |

## 2. ขนาดงานจริง

วัดจากคลังข้อความจริงทั้ง 1,213 คำบรรยาย:

| ประเภท | บรรทัดทั้งหมด | บรรทัดที่ไม่ซ้ำ | **สิ่งที่ต้องแปลจริง** |
|---|---|---|---|
| ป้ายโครงสร้าง (`DEF : 5`) | 1,688 | 226 | **13 ชื่อป้าย** |
| ค่าสถานะล้วน (`ATK +5.`) | 294 | 144 | **56 ชื่อค่าสถานะ** |
| **ร้อยแก้ว** | 1,725 | **1,440** | **1,440 บรรทัด** |

**คอลัมน์สุดท้ายคือตัวเลขที่สำคัญ และมันต่างจากคอลัมน์ก่อนหน้าอย่างมีนัยสำคัญ**

ป้ายโครงสร้างมี 226 บรรทัดที่ไม่ซ้ำ แต่ไม่ต้องแปล 226 ครั้ง เพราะ `Equippable by : All Jobs` กับ `Equippable by : Swordsman Class` ต่างกันแค่**ค่า** ไม่ใช่ป้าย — แปล `Equippable by` ครั้งเดียวแล้วส่งค่าผ่านไปตรงๆ เหลืองานจริง **13 ชื่อป้าย** กับ **56 ชื่อค่าสถานะ**

ถ้าเก็บป้ายโครงสร้างเป็นบรรทัดเต็มในแมพ จำนวนจะบานตามข้อมูลที่เพิ่มเข้ามา — ไอเทมใหม่ที่มีชุดอาชีพต่างออกไปจะกลายเป็นบรรทัดใหม่ที่ต้องแปลอีก ทั้งที่ป้ายเดิม

**ร้อยแก้วต่างออกไป — ต้องเก็บทั้งบรรทัด** เพราะไม่มีโครงสร้างให้แยกป้ายกับค่า `Can be sold to the Collector.` โผล่ 142 ครั้ง แปลครั้งเดียวใช้ได้ทุกที่ รวมอังกฤษที่ต้องแปล ~98,000 ตัวอักษร

ร้อยแก้วแยกเป็นสองพันธุ์ที่ต้องคนละมาตรฐาน:
- **ข้อความเอฟเฟกต์** — แปลผิดคือให้คำตอบผิด ต้องแม่นและครบ
- **ข้อความบรรยาย** (~730 บรรทัดยาวเกิน 60 ตัวอักษร) — แปลผิดไม่มีใครเดือดร้อน แต่แปลแข็งจะอ่านไม่ลื่น

## 3. อภิธานศัพท์ — ล็อกคำก่อนแปล

**เหตุผลที่ต้องมี:** แปล 1,440 บรรทัดเป็นชุดโดยไม่ล็อกคำ คำจะเพี้ยนกันเอง — `defeating` กลายเป็น `สังหาร` บ้าง `กำจัด` บ้าง `ฆ่า` บ้าง ในเว็บเดียวกัน ความไม่สม่ำเสมอทำให้อ่านเหมือนแปลด้วยเครื่อง

### 3.1 กฎหลัก — มาจากหลักฐาน ไม่ใช่ความชอบ

**ศัพท์เกมคงอังกฤษ โครงประโยคเป็นไทย**

ยึดตามที่คำแปลทางการทำ (`มีโอกาสที่จะร่าย 'Curse' ใส่คู่ต่อสู้ เมื่อได้รับ Physical Damage`) และเหตุผลที่หนักกว่านั้น: **เกมแสดงอังกฤษ** ผู้เล่นเปิดกระเป๋าเห็น `Leib Olmai Card` ถ้าเว็บเขียน "การ์ดไลบ์ โอลไม" เขาจับคู่กับของในมือไม่ได้ — แปลแล้วหายากขึ้น ไม่ใช่ง่ายขึ้น

### 3.2 คงอังกฤษเสมอ

- **ชื่อเฉพาะทุกชนิด** — ไอเทม มอนสเตอร์ สกิล NPC แมพ
- **สกิลในวงเล็บเหลี่ยม** คงรูปเดิมทั้งวงเล็บ: `[Heal]`, `[Fire Bolt]`, `[Cloaking]`, `[Soul Strike]`, `[Bash]`, `[Envenom]`, `[Magnum Break]`, `[Endure]`
- **ตัวย่อค่าสถานะ** — `ATK` `DEF` `MATK` `MDEF` `STR` `AGI` `VIT` `INT` `DEX` `LUK` `HIT` `FLEE` `CRIT` `ASPD` `MHP` `MSP` `SP` `HP`
- **ศัพท์กลไก** — `Physical Damage`, `Critical Damage`, `Perfect Dodge`, `Variable Casting Time`, `Damage Taken`, `Resistance`
- **สถานะผิดปกติ** — `Curse`, `Silence`, `Blind`, `Stun`, `Sleep`, `Frozen`, `Poison`, `Petrify`
- **ธาตุ** — `Fire`, `Water`, `Wind`, `Earth`, `Poison`, `Holy`, `Shadow`, `Ghost`, `Undead`, `Neutral`
- **เผ่ามอน** — `Brute`, `Demi-Human`, `Demon`, `Undead`, `Formless`, `Insect`, `Plant`, `Fish`, `Dragon`, `Angel`
- **ช่องสวมใส่** — `Armor`, `Weapon`, `Shield`, `Garment`, `Shoes`, `Accessory`, `Headgear`
- **NPC ที่อ้างถึงบ่อย** — `Collector` (โผล่ 146 ครั้ง)

### 3.5 รูปแบบตัวเลขและเครื่องหมาย

- คงตัวเลขและ `%` ตามต้นฉบับเป๊ะ — ห้ามปัด ห้ามแปลงหน่วย

## 4. สถาปัตยกรรม

### 4.1 สองกลไก ไม่ใช่หนึ่ง

§2 อธิบายไว้แล้วว่าป้ายโครงสร้างกับร้อยแก้วต้องคนละวิธี ตารางจึงมีสองใบ ไม่ใช่ใบเดียว

```sql
-- ร้อยแก้ว: เก็บทั้งบรรทัด เพราะแยกป้ายกับค่าไม่ได้
create table item_description_lines (
  source_line text primary key,     -- บรรทัดอังกฤษ ตรงตัว
  thai_line text not null,
  kind text not null,               -- 'effect' | 'flavour'
  reviewed boolean not null default false,
  updated_at timestamptz not null default now()
);

-- ป้ายและชื่อค่าสถานะ: เก็บเฉพาะคำ ค่าส่งผ่านไปตรงๆ
create table item_description_terms (
  source_term text primary key,     -- 'Equippable by' หรือ 'Perfect Dodge'
  thai_term text,                   -- null = จงใจคงอังกฤษ เช่น ATK, DEF
  kind text not null,               -- 'label' | 'stat'
  updated_at timestamptz not null default now()
);

alter table item_description_lines enable row level security;
alter table item_description_terms enable row level security;

create policy "item_description_lines public read"
  on item_description_lines for select
  to anon, authenticated using (true);

create policy "item_description_terms public read"
  on item_description_terms for select
  to anon, authenticated using (true);
```

**`thai_term` เป็น null ได้โดยตั้งใจ** — `ATK` และ `DEF` อยู่ในตารางแต่ไม่มีคำแปล เพราะกฎ §3.2 บอกให้คงอังกฤษ การมีแถวอยู่แปลว่า "พิจารณาแล้วและตัดสินใจไม่แปล" ซึ่งต่างจาก "ยังไม่ได้ทำ" — ถ้าไม่มีแถว สคริปต์ตรวจจะรายงานว่าตกหล่น

**เหตุผลที่แยกสองตาราง ไม่ใช่ใช้ `kind` แยกในตารางเดียว:** คีย์ต่างชนิดกัน ใบหนึ่งคีย์ด้วยบรรทัดเต็ม อีกใบคีย์ด้วยคำ ถ้ายัดรวมกัน `DEF : 5` กับ `DEF` จะเป็นสองแถวที่หน้าตาเหมือนกันแต่หมายถึงคนละอย่าง และตอนค้นหาจะชนกัน

**เหตุผลที่ไม่เก็บ `description_th` ต่อไอเทม:**

1. บรรทัดเดียวกันได้คำแปลเดียวกัน**เสมอ** — `Can be sold to the Collector.` แปลครั้งเดียว ใช้ 142 ที่
2. แก้คำแปลครั้งเดียว มีผลทุกไอเทมทันที ไม่ต้องไล่แก้
3. **ถอยกลับเป็นอังกฤษได้ทีละบรรทัด** — แปลไป 30% ก็ปล่อยได้ ไม่ต้องรอครบ
4. วัดความคืบหน้าได้ตรงๆ: `count(*) / 1440`

**RLS อยู่ใน migration เดียวกับที่สร้างตาราง** — v1 เคยพลาดจนคีย์ anon ลบข้อมูลได้

### 4.2 การประกอบข้อความ

```ts
// lib/item-description-th.ts
export interface DescriptionLine {
  source: string;
  thai: string | null;   // null = ยังไม่แปล แสดงอังกฤษ
}

export function composeThaiDescription(
  description: string | null,
  lineMap: ReadonlyMap<string, string>,
): DescriptionLine[]
```

แยกบรรทัด ตัดโค้ดสี หาในแมพ ถ้าไม่เจอคืน `thai: null` แล้วหน้าเว็บแสดงอังกฤษบรรทัดนั้น

### 4.3 การแสดงผล

หน้า item detail แสดง**ไทยเป็นหลัก** และมีปุ่มสลับดูอังกฤษ เก็บค่าที่เลือกใน `localStorage`

**เหตุผลที่ต้องมีปุ่มสลับ ไม่ใช่แสดงไทยอย่างเดียว:** ผู้เล่นบางคนคุ้นข้อความอังกฤษจากในเกม และเมื่อคำแปลของเรากับข้อความในเกมไม่ตรงกัน เขาต้องเทียบได้

บรรทัดที่ยังไม่แปลแสดงอังกฤษตามปกติ **ไม่ต้องมีป้ายบอกว่ายังไม่แปล** — ผู้ใช้ไม่ต้องรู้สถานะงานของเรา

## 5. ลำดับการแปล

เรียงตามผลกระทบต่อผู้ใช้ ไม่ใช่ตามความง่าย:

**ชุด 1 — ป้ายและค่าสถานะ (13 + 56 รายการ)**
แปล 69 รายการ ครอบคลุม 1,982 บรรทัด คิดเป็น **53% ของบรรทัดทั้งหมด** — อัตราส่วนดีที่สุดในงานนี้ และเป็นเหตุผลที่ต้องทำก่อน

**ชุด 2 — ข้อความเอฟเฟกต์ความถี่สูง**
บรรทัดที่โผล่ตั้งแต่ 3 ครั้งขึ้นไป — จำนวนน้อย ผลกระทบสูง และเป็นส่วนที่ความแม่นยำสำคัญที่สุด

**ชุด 3 — เอฟเฟกต์ที่เหลือ**
บรรทัดเอฟเฟกต์ที่โผล่ 1-2 ครั้ง

**ชุด 4 — ข้อความบรรยาย (~730 บรรทัด)**
ทำท้ายสุด เพราะแปลผิดไม่กระทบการตัดสินใจของผู้เล่น

แปลเป็นชุดละ ~50 บรรทัด แต่ละชุดตรวจกับอภิธานศัพท์ก่อนบันทึก

### 6.1 ตรวจอัตโนมัติ — สคริปต์ตรวจอภิธานศัพท์

`scripts/check-thai-glossary.ts` อ่านทุกแถวใน `item_description_lines` แล้วรายงาน:

1. **คำที่ต้องคงอังกฤษแต่ถูกแปล** — ถ้า source มี `Curse` แต่ thai ไม่มี `Curse` → ผิด
2. **คำที่ล็อกไว้แต่ใช้คำอื่น** — ถ้า source มี `defeating` แต่ thai มี `กำจัด` แทน `สังหาร` → ผิด
3. **ตัวเลขไม่ตรง** — ดึงตัวเลขทั้งหมดจาก source และ thai ถ้าชุดไม่ตรงกัน → ผิด **นี่คือด่านสำคัญที่สุด** เพราะเป็นความผิดพลาดชนิดเดียวที่ทำให้ผู้เล่นตัดสินใจผิด
4. **บรรทัดที่ยังเป็นอังกฤษล้วน** — ไม่มีอักษรไทยเลย อาจลืมแปล

**สคริปต์นี้ต้องเขียนก่อนแปลชุดแรก** ไม่ใช่หลังแปลเสร็จ

### 6.2 เทสต์

| ไฟล์ | เทสต์อะไร | เคสที่ห้ามลืม |
|---|---|---|
| `lib/item-description-th.ts` | ประกอบข้อความ | description เป็น null · บรรทัดที่ไม่มีในแมพ · โค้ดสี `^FF0000` ถูกตัด · บรรทัดว่าง |
| `scripts/check-thai-glossary.ts` | ตัวตรวจ | ตัวเลขไม่ตรงต้องจับได้ · ศัพท์ที่ควรคงอังกฤษแต่ถูกแปลต้องจับได้ |

**บังคับ:** เขียนเทสต์แล้วต้องพิสูจน์ว่ามันแดงได้จริง — ป้อนคำแปลที่จงใจผิดตัวเลข แล้วดูว่าตัวตรวจจับได้ไหม

### 6.3 ตรวจด้วยตา

หลังทุกชุด เปิดหน้า item detail จริง 3 ไอเทมจากชุดนั้น ดูว่าอ่านลื่นและไม่มีคำอังกฤษโผล่กลางประโยคแบบไม่ตั้งใจ

## 8. ไม่อยู่ในงานนี้

- **`name_th` ของไอเทมและมอนสเตอร์** — ชื่อคงอังกฤษตามกฎ §3.1 สองคอลัมน์นั้นยังว่างและยังไม่มีโค้ดอ่าน ถ้าจะใช้ในอนาคตควรเก็บ**ชื่อที่คนไทยเรียกกันจริง** (`ถ้ำพะยอน`) ไม่ใช่คำแปล และเริ่มจากแมพ ไม่ใช่ไอเทม
- **คำบรรยายสกิลและมอนสเตอร์** — งานคนละก้อน โครงสร้างที่นี่รองรับได้ถ้าจะขยาย
- **สลับภาษาทั้งเว็บ** — งานนี้ทำเฉพาะคำบรรยายไอเทม ตัวเว็บเป็นไทยอยู่แล้ว
