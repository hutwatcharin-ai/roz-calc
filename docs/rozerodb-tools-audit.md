# สำรวจเครื่องมือของ rozerodb.com — รายละเอียด ข้อแตกต่าง และแนวทางออกแบบที่ดีกว่า

วันที่สำรวจ: 26 สิงหาคม 2569
วิธีสำรวจ: ดึง HTML ของหน้าเว็บโดยตรง (`curl` + WebFetch) และอ่านโครงเมนูจาก JS bundle ของเว็บ ไม่ได้แตะ endpoint `/api/`

## สรุปสั้น

rozerodb.com คือฐานข้อมูล Ragnarok Zero Global ที่ครบที่สุดเท่าที่มีตอนนี้ มี 3 ชั้น: **ฐานข้อมูล 9 หมวด** + **ไกด์ 8 หน้า** + **เครื่องมือ 8 ตัว** (และ DPS Calculator ที่ขึ้นเมนูไว้แต่ยังปิดอยู่) จุดแข็งคือความครบและความสดของข้อมูล จุดอ่อนคือทุกอย่างเป็นภาษาอังกฤษล้วน เครื่องมือแต่ละตัวแยกกันเป็นเอกเทศ และหลายตัวต้องให้ผู้เล่นกรอกตัวเลขที่ตัวเองไม่รู้ (เช่น kills/hour) — ซึ่งคือช่องว่างที่ ROZ Calc แทรกได้จริง

## 2. รายละเอียดเครื่องมือทีละตัว

### 2.1 EXP Calculator (`/tools/exp`)

**อินพุต:** เลเวลปัจจุบันและเป้าหมาย (Base 1–50), ติ๊กคำนวณ Job EXP ด้วยหรือไม่ (Job 1–50), เลือกมอนสเตอร์, ติ๊กซ่อนมอนที่ชื่อขึ้นต้นด้วยรหัส C, จำนวนคิลต่อชั่วโมง (ค่าเริ่มต้นคิดที่ประมาณ 12 วินาทีต่อตัว), ช่องปรับ EXP อื่น ๆ เป็นเปอร์เซ็นต์ (เริ่มที่ 100%), ขนาดปาร์ตี้ (เดี่ยวถึง 12 คน พร้อมโบนัส 0% ถึง 220%), จำนวนคนที่ตีจริง

**เอาต์พุต:** จำนวนคิลที่ต้องใช้ทั้งหมด, เวลาโดยประมาณ, Base EXP ที่ต้องการ, EXP ต่อคิลหลังคูณตัวคูณ, EXP ต่อชั่วโมง, ชุดเดียวกันสำหรับ Job EXP และตารางแบ่ง EXP ปาร์ตี้ 2–12 คน

**ข้อสังเกตที่เว็บประกาศเอง:** ใช้ตาราง EXP ทางการของ Zero Global, ไม่รวม Novice Job EXP, และ **ไม่ใส่ค่าปรับตามส่วนต่างเลเวลให้อัตโนมัติ** — ตรงกับสิ่งที่ผู้เล่นยืนยันว่า Zero ไม่มีขั้นบันได EXP

### 2.2 Farm / Drop Planner (`/tools/farm-drop-planner`)

**อินพุต:** เลือกมอนสเตอร์ (โหมดตัวเดียว หรือโหมดผสมทั้งเส้นทาง), คิลต่อชั่วโมง (กรอกเองหรือใช้ตัวช่วยนับ 3–5 นาทีแล้วคำนวณให้), ช่องปรับโบนัส Base EXP / Job EXP / Drop แยกกัน แต่ละช่องมีติ๊ก "+10% item boost", และสวิตช์จำลอง Steal ที่ใช้ DEX ผู้เล่น DEX มอน และเลเวลสกิล

**เอาต์พุต:** เทียบ EXP ต่อชั่วโมง, ของที่ได้ต่อชั่วโมง, และโอกาสได้ของหายากอย่างน้อยหนึ่งชิ้นหลังตี N ตัว (jackpot odds) ข้ามหลายแมพ

**สูตรที่ประกาศ:** EXP ต่อคิล × คิลต่อชั่วโมงสุทธิ × โบนัส และโบนัสดรอปคือคูณ 1.10 โดยเพดานที่ 100% ส่วนมูลค่าเซนีคิดจากจำนวนที่คาดว่าจะได้ × ราคาขาย NPC ของที่ไม่มีราคาจะไม่ถูกนับ และเว็บระบุชัดว่าตัวเลข Steal ไม่ใช่พฤติกรรมที่ยืนยันแล้วของ Zero

### 2.3 Refine Simulator (`/tools/refine`)

**อินพุต:** ประเภทของ (Armor / Weapon แยกตามระดับ), ระดับตีบวกเป้าหมาย +0 ถึง +20, ชนิดแร่ (Oridecon หรือ Concentrated)

**เอาต์พุต:** อัตราสำเร็จรายขั้น (เช่น +0 ไป +1 ที่ 90%, ขั้น +10 ที่ 9%), ความน่าจะเป็นที่จะสำเร็จรวดเดียวตลอดเส้นทาง (เช่น +0 ไป +10 ได้ 0.0202%), ค่าธรรมเนียม 10,000 เซนีต่อครั้ง, และผลเมื่อพลาดคือของแตก พร้อมตารางโบนัส ATK/MATK รายระดับ +1 ถึง +20 ที่มีทั้งค่าพื้นฐานและช่วงสุ่มเพิ่ม

**ที่มาที่เว็บอ้าง:** ข้อมูล Global อย่างเป็นทางการ

### 2.4 Affixes Simulator (`/tools/affixes`)

**อินพุต:** ประเภทของ (Armor, Garment, Magic Series, Melee Series, Ranged Series, Shoes) และแหล่งที่มาของ affix (Monster Drop, MVP Drop, Blacksmith Forging, Activation System, Glast Heim)

**เอาต์พุต:** ตารางพูลของ affix แยกตามช่อง (ปกติ 3 ช่อง) แต่ละรายการบอกชื่อสเตตัส หมายเลขพูล และช่วงค่าต่ำสุด-สูงสุด เช่น Armor ช่องแรกมี MaxHP ช่วง 150–350 นับรวมทั้งเว็บ 595 affix โดยเฉพาะ Monster Drop ของ Armor มี 235 ตัวเลือก

**ข้อจำกัดที่สำคัญ:** ชื่อว่า Simulator แต่**ไม่ได้สุ่มจริง** เป็นตารางอ้างอิงเฉย ๆ และเว็บระบุเองว่ากำลังตรวจสอบค่าเทียบกับตาราง affix ในไฟล์เกม

### 2.5 Skill Tree (`/tools/skill-tree`)

เลือกอาชีพและสายที่จะเปลี่ยน (เช่น Swordsman ไป Knight), กดเพิ่มลดเลเวลสกิลทีละจุด, แยกนับแต้ม 1st Job และ 2nd Job, **ลงสกิลที่ต้องมีก่อนให้อัตโนมัติ** เมื่อกดสกิลปลายทาง และถอดสกิลที่ค้างเงื่อนไขให้เมื่อลดต้นทาง แต่ละโหนดบอกไอคอน ชื่อ ประเภท Active/Passive ธาตุ เลเวลปัจจุบัน/สูงสุด เงื่อนไขที่ต้องมีก่อน และลิงก์ไปหน้าสกิลเต็ม มีปุ่ม Copy link สำหรับแชร์บิลด์ พร้อม Undo / Redo / Reset

**นี่คือเครื่องมือที่ทำได้ดีที่สุดในเว็บ** ทั้งเรื่องความถูกต้องของเงื่อนไขและ UX

### 2.6 Forge Simulator (`/tools/forge`)

**อินพุต:** INT / DEX / LUK ของช่างตีเหล็กพร้อมตัวปรับจากบัฟ โบนัสอาชีพ อาหาร และกิลด์, เลเวลอาชีพ, เลเวลสกิล Smith Weapon / Iron Tempering / Steel Tempering / Enchanted Stone, ชนิดทั่ง (ธรรมดา / Golden / Imperium), วัสดุ (Iron, Steel, Elemental Stone), ระดับอาวุธ Lv.1–3 และจำนวน Star Crumb 0–3

**เอาต์พุต:** อัตราสำเร็จของแต่ละส่วนผสม เช่น Lv.1 Iron อยู่ที่ 92.6% และลดเหลือ 42.6% เมื่อใส่ Star Crumb 3 ชิ้น

**ข้อสังเกตที่เว็บประกาศเอง:** สูตรมาจากการดูสตรีมฝั่ง TwRO และยังไม่ยืนยันในเกมจริง

### 2.7 Alchemist Brewing Simulator (`/tools/alchemist`)

**อินพุต:** INT / DEX / LUK, เลเวลอาชีพ, บัฟ (Blessing, Gloria, Marionette, Song, Battle Chant, อาหาร, กิลด์, Yggdrasil Blessing), เลเวลสกิล Potion Research 0–10, Pharmacy 0–10, Instruction Change 0–5 และชนิดยาที่จะต้ม

**เอาต์พุต:** เปอร์เซ็นต์สำเร็จ, ค่าปรับตามชนิดยา (ช่วง -20 ถึง +10) และแต้มต่อการต้มหนึ่งครั้ง

**ข้อสังเกต:** เว็บระบุว่ายังต้องยืนยันว่า Instruction Change ให้ INT +5 จริงหรือไม่ และสูตรที่ใช้เป็นสูตรดั้งเดิมที่บวกค่าสกิลตรง ๆ

### 2.8 Arrow Crafting (`/tools/arrow-crafting`)

ค้นได้สองทาง คือค้นจากชนิดลูกธนู หรือค้นจากวัสดุ แสดงลูกธนู 21 ชนิด วัสดุ 135 อย่าง รวม 217 สูตร แต่ละรายการบอกไอคอน ชื่อ item ID และอัตราแปลง เช่นวัสดุหนึ่งชิ้นได้ลูกธนูกี่ดอก

## 3. ข้อค้นพบเชิงเทคนิคที่กระทบข้อสรุปเดิมของโปรเจกต์

ใน `docs/superpowers/specs/2026-08-26-roz-calc-v2-design.md` หัวข้อ 2 เคยบันทึกว่า *"rozerodb.com `/api/` — robots.txt ของเขาเอง Disallow: /api/ (หน้า tool ไม่มีตัวเลขใน HTML โหลดจาก API)"* และใช้เป็นเหตุผลหนึ่งในการตัดกลุ่มเครื่องมือคำนวณทิ้งทั้งกลุ่ม

**ครึ่งหลังของประโยคนั้นไม่ตรงกับที่ตรวจพบวันนี้** ทดสอบด้วย `curl` โดยไม่รันจาวาสคริปต์:

- `/tools/refine` ขนาด 22 KB มีทั้งค่าธรรมเนียม 10,000 และตัวเลขความน่าจะเป็นสะสม 0.0202 อยู่ใน HTML
- `/tools/affixes` ขนาด 114 KB มีคำว่า POOL 43 ครั้ง MaxHP 16 ครั้ง และค่าขอบเขต 150 กับ 350 อยู่ใน HTML

แปลว่าตัวเลขของเครื่องมืออย่างน้อยสองตัวถูก server-render มาในหน้าเลย ไม่ได้ซ่อนหลัง API

ส่วน robots.txt ของเขาคือ `Allow: /` และ `Disallow: /api/` เท่านั้น การเปิดอ่านหน้าเว็บปกติจึงไม่ได้ถูกห้าม

**แต่ข้อสรุป "ตัดกลุ่มเครื่องมือคำนวณ" ยังควรยืนตามเดิม** ด้วยเหตุผลที่แข็งแรงกว่าเรื่องเข้าถึงได้หรือไม่:

1. การดูดตารางของเขามาทั้งชุดคือการทำสำเนาฐานข้อมูลของเว็บอื่น ต่อให้ robots.txt ไม่ห้าม ก็เป็นคนละเรื่องกับการมีข้อมูลเป็นของตัวเอง และทำให้เว็บเราผิดตามเขาทุกครั้งที่เขาผิด
2. ตัวเขาเองประกาศว่าหลายชุดยังไม่ยืนยัน — affix ยังตรวจกับไฟล์เกมอยู่ forge มาจากการดูสตรีม alchemist ยังไม่ยืนยันสกิลตัวหนึ่ง การลอกมาคือการลอกความไม่แน่นอนมาด้วย
3. ทางที่ถูกกว่าและไม่ติดข้อจำกัดใดเลยคือดึงจากไฟล์เกมเอง ตามที่ v2 spec หัวข้อ 3.11 สรุปไว้แล้ว

## 5. จุดอ่อนของ rozerodb ที่เป็นช่องว่างจริง

1. **ต้องกรอกตัวเลขที่ผู้เล่นไม่รู้** ทั้ง EXP Calculator และ Farm Planner เริ่มจากคำถามว่า "คุณตีได้กี่ตัวต่อชั่วโมง" ซึ่งคนที่ยังไม่ได้ไปลองยืนตีจะตอบไม่ได้ Farm Planner ถึงกับต้องมีตัวช่วยให้ไปนับเองสามถึงห้านาที
2. **เครื่องมือแยกกันเป็นเกาะ** ตั้งค่าเลเวล อาชีพ ของสวมใส่ในเครื่องมือหนึ่งแล้ว อีกเครื่องมือไม่รู้เลย ต้องกรอกใหม่ทุกหน้า
3. **Affixes Simulator ไม่ได้จำลองอะไรเลย** เป็นตารางพูลล้วน ๆ ตอบได้แค่ว่า "ของชิ้นนี้มีโอกาสออกอะไรบ้าง" ตอบไม่ได้ว่า "ของที่ฉันเพิ่งดรอปมาถือว่าดีแค่ไหน"
4. **ไม่มีสะพานจากฐานข้อมูลไปสู่การตัดสินใจ** หน้ามอนสเตอร์บอกดรอปครบ แต่ไม่บอกว่ามอนตัวนี้ปล่อยบอททิ้งไว้ได้ไหม ซึ่งเป็นคำถามแรกของเซิร์ฟที่ทุกคนเปิดบอท
5. **อังกฤษล้วน** ผู้เล่นไทยจำนวนมากอ่านชื่อสกิลอังกฤษออกแต่ไม่อ่านคำอธิบายยาว ๆ
6. **Refine Simulator ตอบแค่ความน่าจะเป็น** ไม่ได้ตอบคำถามที่คนถามจริงว่า "กว่าจะได้ +7 ต้องเตรียมแร่กี่ก้อนและเงินเท่าไร"

## 6. แนวทางออกแบบที่ดีกว่า

ข้อเสนอด้านล่างเรียงจากผลตอบแทนต่อแรงลงมาก ทุกข้อใช้ข้อมูลที่โปรเจกต์มีอยู่แล้วหรือหาได้จากไฟล์เกม ไม่ต้องลอกตารางของใคร

### 6.1 คิด kills/hour ให้ผู้เล่น แทนที่จะถาม

นี่คือข้อได้เปรียบที่ตรงที่สุด เรามี HP ของมอนทุกตัวอยู่แล้ว ให้ผู้ใช้กรอกดาเมจต่อครั้งกับความเร็วโจมตี (หรือเลือกอาชีพและเลเวลแล้วให้ประมาณให้) แล้วคำนวณเวลาต่อคิลเอง จากนั้น EXP ต่อชั่วโมงและของต่อชั่วโมงจะไหลออกมาเองทั้งหมด

ตัวเลขจากงานวิจัยคลิปที่รองรับแนวทางนี้: อัตราส่วน EXP ต่อ HP ของมอนทั้งเซิร์ฟอยู่ราว 0.6 ซึ่งแปลว่าถ้ารู้ DPS ก็ประมาณ EXP ต่อชั่วโมงได้แม้ยังไม่รู้ว่าจะไปตีตัวไหน ใช้เป็นค่าอ้างอิงสำหรับตรวจว่าผลลัพธ์ที่คำนวณได้สมเหตุสมผลไหม

### 6.2 ธง "ปล่อยบอทได้ไหม" ในทุกหน้ามอนสเตอร์และทุกผลการค้นหา

คำถามแรกของเซิร์ฟที่ทุกคนเปิดบอทคือ "ตัวนี้เข้ามาตีเราเองหรือเปล่า" เพราะมอนที่ active attack คือสาเหตุหลักที่ตายตอน AFK แล้วเสีย EXP 10%

ทำเป็นป้ายสามระดับ: ปลอดภัย (ไม่เข้าตีเอง) / ระวัง (เข้าตีเองแต่เบา) / อันตราย (เข้าตีเองและแรง) แล้วให้กรองได้จากหน้ารายการ นี่คือสิ่งที่ rozerodb ไม่ได้ทำ ทั้งที่ข้อมูลอยู่ในไฟล์เกม และ v2 spec ข้อ 3.8 ก็วางแผนหน้านี้ไว้แล้ว — ข้อเสนอเพิ่มคือ **อย่าให้อยู่แค่หน้าแยก ให้ป้ายนี้ติดไปกับมอนทุกที่ที่มอนปรากฏ**

### 6.3 บริบทตัวละครร่วมกันทุกเครื่องมือ

เก็บเลเวล อาชีพ ดาเมจ และบัฟที่ใช้ไว้ที่เดียว (localStorage ก็พอ ไม่ต้องมีระบบสมาชิก) แล้วให้ทุกหน้าอ่านค่าเดียวกัน ผลคือ:

- หน้าฐานข้อมูลมอนสเตอร์แสดงเลยว่า "ตัวนี้คุณตีกี่ทีตาย" และ "EXP ต่อชั่วโมงถ้าคุณยืนตีตรงนี้"
- Drop finder เรียงผลตาม "เวลาที่คุณต้องใช้จริงกว่าจะได้ของชิ้นนี้" ไม่ใช่แค่เปอร์เซ็นต์ดรอป
- หน้าแรกกลายเป็น "วันนี้ควรไปไหน" ที่ตอบเฉพาะตัว

อันนี้เป็นข้อได้เปรียบเชิงโครงสร้างที่เว็บซึ่งทำเครื่องมือแยกเป็นเกาะไล่ตามได้ยาก

### 6.4 เปลี่ยนตาราง affix เป็นเครื่องให้คะแนนของที่ดรอปมา

แทนที่จะโชว์พูลเฉย ๆ ให้ผู้ใช้กรอกสิ่งที่ตัวเองได้มา (เช่น MaxHP 210, Flee 9) แล้วเว็บตอบว่าอยู่ที่เปอร์เซ็นไทล์เท่าไรของช่วงที่เป็นไปได้ และคุ้มจะเก็บไว้หรือขาย พร้อมพรีเซ็ตว่าอาชีพไหนควรมองหา affix ตัวไหน (เช่น ต้นเกมมองหา Max HP กับ Flee ก่อน เพราะมอนต้นเกม hit แค่ 200–300)

ค่าที่ต้องใช้คือช่วงต่ำสุด-สูงสุดของแต่ละ affix ซึ่งควรดึงจากไฟล์เกม ไม่ใช่จากหน้าเว็บของเขา

### 6.5 ตอบเป็นต้นทุน ไม่ใช่เป็นเปอร์เซ็นต์

เวลาคนถามเรื่องตีบวก เขาไม่ได้อยากได้เลข 9% เขาอยากรู้ว่าต้องเตรียมอะไรบ้าง ให้แสดงเป็น "จำนวนแร่ที่คาดว่าจะใช้ + เงินที่คาดว่าจะเสีย + โอกาสที่ของจะแตกระหว่างทาง" สำหรับเป้าหมายที่เลือก และถ้าวันหนึ่งมีข้อมูลราคาตลาด ให้เทียบต่อว่าซื้อของ +7 สำเร็จรูปถูกกว่าตีเองหรือไม่

หลักการเดียวกันใช้กับทุกเครื่องมือสุ่ม: คำตอบที่ดีคือหน่วยที่ผู้เล่นจ่ายจริง ได้แก่ เวลา เงิน และของ

### 6.6 ไกด์ที่อ้างอิงได้ ไม่ใช่ไกด์ลอย

ไฟล์ `docs/youtube-research-roz.md` มีวัตถุดิบพร้อมแล้วจาก 40 คลิป จุดต่างที่ทำได้คือทุกข้อความบนหน้าไกด์บอกได้ว่ามาจากไหนและยืนยันแล้วหรือยัง โดยเฉพาะจุดที่แหล่งข้อมูลยังขัดกันเอง เช่น อัตราตีบวกของสองช่องที่ไม่ตรงกัน หรือคำถามว่าปาร์ตี้ช่วยเก็บเลเวลจริงไหม การยอมบอกว่า "ข้อนี้ยังไม่ชัด" คือสิ่งที่เว็บฐานข้อมูลทั่วไปไม่ทำ และเป็นเหตุผลให้คนกลับมา

### 6.7 ช่องว่างที่ยังว่างอยู่ทั้งสองเว็บ

- **DPS Calculator** เขาประกาศไว้แต่ยังไม่เปิด ถ้าเราทำก่อนและทำให้เชื่อมกับบริบทตัวละคร (ข้อ 6.3) จะกลายเป็นแกนของทั้งเว็บ เพราะทุกอย่างตั้งแต่ kills/hour ยันเวลาที่ต้องใช้กว่าจะได้ของ ล้วนต่อยอดจากตัวเลขนี้
- **ตัววางแผนสายอัปเกรดชุดจากดัน** (Subjugation ไป Expedition ไป Contingent ไป Conqueror) ยังไม่มีใครทำเป็นหน้าเดียวจบ ทั้งที่เป็นระบบที่ถ้ารู้ช้าจะตามยากมาก
- **หน้า "ของชิ้นนี้ใส่ได้เดือนไหน"** ที่ผูกของเข้ากับ roadmap การปลดเลเวล

### 6.8 สิ่งที่ควรลอกเขาตรง ๆ

ไม่ใช่ทุกอย่างต้องคิดใหม่ สองอย่างนี้เขาทำถูกแล้วและควรทำตาม:

- **การลงสกิลที่ต้องมีก่อนให้อัตโนมัติ** ใน Skill Tree เป็นพฤติกรรมที่ถูกต้องและลดความหงุดหงิดได้มาก ถ้าเราทำ Stat/Build Calculator ควรมีตั้งแต่วันแรก
- **ปุ่มคัดลอกลิงก์เพื่อแชร์บิลด์** ทำให้เครื่องมือกลายเป็นสิ่งที่ถูกส่งต่อในกลุ่มและดิสคอร์ด ซึ่งเป็นช่องทางที่เว็บใหม่ต้องการที่สุด

## 7. ข้อควรระวังเรื่องที่มาข้อมูล

- robots.txt ของ rozerodb เปิดให้เข้าถึงทุกหน้ายกเว้น `/api/` การเปิดอ่านหน้าเว็บเพื่อศึกษาโครงสร้างจึงไม่ผิดกติกาของเขา และไฟล์นี้ก็ทำแค่นั้น
- แต่การดูดข้อมูลของเขามาเป็นฐานข้อมูลของเราเป็นคนละเรื่อง และไม่ควรทำ ทั้งด้วยเหตุผลด้านความถูกต้อง (เขาเองยังไม่ยืนยันหลายชุด) และด้านความยั่งยืนของโปรเจกต์
- แนวทางที่ v2 spec สรุปไว้แล้วยังถูกต้อง คือไฟล์เกมเป็นแหล่งที่ดีที่สุดและไม่ติดข้อจำกัดใด ๆ
- ตัวเลขทุกตัวในไฟล์นี้คือสิ่งที่ **rozerodb แสดง** ไม่ใช่สิ่งที่เรายืนยันเอง ถ้าจะเอาไปใช้ต้องตรวจซ้ำจากไฟล์เกมหรือในเกมก่อน

## 8. ลำดับที่แนะนำ

1. ธง active attack ติดทุกที่ที่มอนปรากฏ (ข้อ 6.2) — ใช้ข้อมูลที่มีอยู่แล้ว ได้ผลทันที และไม่มีใครทำ
2. บริบทตัวละครร่วม + คิด kills/hour ให้ (ข้อ 6.1, 6.3) — เปลี่ยนทั้งเว็บจากฐานข้อมูลเป็นผู้ช่วยตัดสินใจ
3. DPS Calculator (ข้อ 6.7) — ช่องว่างที่ยังว่าง และเป็นแกนของข้อ 1 กับ 2
4. เครื่องให้คะแนน affix (ข้อ 6.4) — รอข้อมูลช่วงค่าจากไฟล์เกม
5. ไกด์ที่อ้างอิงได้ (ข้อ 6.6) — วัตถุดิบพร้อมแล้ว เหลือแค่ลงมือ
