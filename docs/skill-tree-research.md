# Skill Tree — ข้อมูลที่ต้องมี ช่องว่างที่มี และแนวทางออกแบบ UI

วันที่: 26 สิงหาคม 2569
ขอบเขต: รวบรวมทุกอย่างที่ต้องรู้ก่อนทำหน้า skill tree ของ ROZ Calc พร้อมแนวทาง UI ที่ให้ความรู้สึกใกล้เคียงหน้าต่างสกิลในเกม

## 1. สรุปสถานะ

เรามีรายชื่อสกิล 851 รายการ แต่**ยังไม่มีข้อมูลที่ทำให้มันเป็น "ต้นไม้" ได้เลย** ส่วนที่ขาดคือเงื่อนไขสกิลที่ต้องมีก่อน ซึ่งเป็นหัวใจทั้งหมดของฟีเจอร์นี้ ถ้าไม่มีข้อมูลนี้ หน้า skill tree จะทำได้แค่ตารางรายชื่อ ซึ่งซ้ำกับ skills browser ที่วางแผนไว้ใน v2 อยู่แล้ว

**ข้อสรุป: ยังทำไม่ได้ในตอนนี้ ต้องหาข้อมูล prerequisite ให้ได้ก่อน** เอกสารนี้เตรียมทุกอย่างที่เหลือไว้ให้พร้อมลงมือทันทีที่ได้ข้อมูล

## 2. ข้อมูลที่ต้องมี

### จำเป็น ขาดไม่ได้

| ฟิลด์ | ใช้ทำอะไร | เรามีไหม |
| --- | --- | --- |
| `slug` / `name` / `icon` | แสดงผล | **มีครบ 851** |
| `max_level` | เพดานการลงแต้ม | มี 846/851 |
| `job` | สกิลนี้อยู่ต้นไม้ของอาชีพไหน | **มีแค่ 433/851** |
| `tier` (1st / 2nd) | แยกกระเป๋าแต้มสองใบ | **ไม่มี** |
| `requires[]` | รายการสกิลที่ต้องลงก่อน พร้อมเลเวลขั้นต่ำ | **ไม่มีเลย** |
| `job_level_req` | บางสกิลต้องถึง job level เท่าไร | **ไม่มี** |

### ควรมี ทำให้ใช้งานได้จริง

| ฟิลด์ | ใช้ทำอะไร | เรามีไหม |
| --- | --- | --- |
| `type` (active/passive) | ป้ายบนโหนด | มี 403/851 |
| `element` | ป้ายธาตุ | มี 160/851 |
| `level_rows[]` | ค่าต่อเลเวล เช่น ดาเมจ SP ที่ใช้ คูลดาวน์ | **ไม่มี** |
| `sp_cost` | คำนวณความคุ้มตอนวางแผน | **ไม่มี** |
| `description` | tooltip | **ไม่มี** |

### ถ้ามีจะดีมาก

- `position` (แถว/คอลัมน์ในตาราง) — ถ้าไม่มี ต้องคำนวณตำแหน่งเองจากกราฟ prerequisite
- ความสัมพันธ์ข้ามอาชีพ เช่น สกิล 2nd job ที่ต้องมีสกิล 1st job เป็นเงื่อนไข

## 3. โครงสร้างที่ควรลอกแนวคิด (จากการสังเกต rozerodb)

เครื่องมือของเขาเป็นตัวที่ทำได้ดีที่สุดในเว็บนั้น แนวคิดที่ควรนำมาใช้:

- **`requires[]` แต่ละรายการมีธง internal / external** — internal คือสกิลที่อยู่ในต้นไม้อาชีพเดียวกัน external คือสกิลนอกต้นไม้ที่ยังไม่มีข้อมูล เมื่อเจอ external ระบบจะไม่พัง แต่ขึ้นข้อความว่า "ข้อมูลเงื่อนไขภายนอก: ..." แทน
- **ตรวจ prerequisite เป็นวงกลม** ถ้าข้อมูลผิดจนวนเป็นลูป ระบบจับได้และแจ้งชื่อสกิลที่เป็นต้นเหตุ แทนที่จะค้างหรือ stack overflow
- **จับกรณีข้อมูลเงื่อนไขหาย** แจ้งว่า "ไม่พบข้อมูลเงื่อนไข: ชื่อสกิล" แทนการเงียบ
- **กระเป๋าแต้มสองใบแยกกัน** นับ 1st Job Points และ 2nd Job Points คนละก้อน
- **ลงเงื่อนไขให้อัตโนมัติ** กด + ที่สกิลปลายทาง ระบบไล่ลงสกิลต้นทางที่จำเป็นให้ครบก่อน และเมื่อลดสกิลต้นทาง สกิลปลายทางที่ค้างเงื่อนไขจะถูกถอดออกตาม
- **Undo / Redo / Reset และปุ่มคัดลอกลิงก์**

สามข้อแรกคือการออกแบบให้ทนต่อข้อมูลไม่สมบูรณ์ ซึ่งตรงกับสภาพข้อมูลของเราพอดี ควรทำตั้งแต่วันแรก

## 4. ทางได้ข้อมูล prerequisite

เรียงตามที่ควรใช้:

1. **ไฟล์เกม** — ตามที่ v2 spec หัวข้อ 3.11 สรุปไว้ว่าเป็นแหล่งที่ดีที่สุดและไม่ติดข้อจำกัดใด ๆ ข้อมูลผังสกิลอยู่ในไฟล์ข้อมูลของ client ทางนี้ได้ทั้ง prerequisite, job level requirement, ค่าต่อเลเวล และ SP ครบในคราวเดียว
2. **ผู้เล่นถ่ายหน้าจอในเกม** — หน้าต่างสกิลในเกมแสดงเงื่อนไขอยู่แล้ว ทำได้ทันทีถ้ามีคนช่วยเก็บ แต่ 6 อาชีพคลาส 1 บวกคลาส 2 อีกสิบกว่าสาย = งานเก็บภาพจำนวนมาก เหมาะเป็นทางเสริมสำหรับตรวจสอบมากกว่าทางหลัก
3. **rozerodb เป็นชุดตรวจสอบเท่านั้น** — ใช้เทียบว่าที่เราอ่านจากไฟล์เกมถูกไหม ไม่ใช่เอามาเป็นฐานข้อมูล ตามหลักเดียวกับที่ตัดสินใจไว้ในเรื่องอัตราตีบวก
4. **เว็บทางการ `roz.mygnjoy.com` ใช้ไม่ได้** — robots.txt ระบุ `User-agent: ClaudeBot` / `Disallow: /` ตรงตัว เช่นเดียวกับ ragnarokzero.wiki และ ragnarokze.ro

## 5. แนวทางออกแบบ UI

### 5.1 หลักการตั้งต้น

ให้ผู้เล่นรู้สึกว่า "นี่คือหน้าต่างสกิลที่ฉันเห็นในเกม" ภายในสองวินาทีแรก แล้วค่อยได้เปรียบตรงที่เว็บทำสิ่งที่เกมทำไม่ได้ — วางแผนล่วงหน้าโดยไม่ต้องใช้แต้มจริง ย้อนกลับได้ และแชร์ให้เพื่อนดูได้

ข้อควรระวัง: **ไม่ใช่การลอกหน้าตาเกมมาทั้งดุ้น** แต่ยืมสิ่งที่คนจำได้ ได้แก่ การจัดวางเป็นตารางไอคอน ตัวเลขเลเวลบนโหนด แถบแต้มคงเหลือด้านบน และเส้นโยงเงื่อนไข

### 5.2 โครงหน้าจอ (จอใหญ่)

สามส่วนแนวนอน:

```
┌──────────────────────────────────────────────────────────┐
│  [ไอคอนอาชีพ] Knight        1st 40/49   2nd 12/58        │  ← แถบติดบนเสมอ
│  Swordsman → Knight ▾       [Reset] [Undo] [Redo] [Copy] │
├──────────────────────────┬───────────────────────────────┤
│                          │  Bowling Bash                 │
│   ตารางสกิล + เส้นเชื่อม  │  Active · Lv 5/10             │
│   (พื้นที่หลัก)           │  ต้องมี: Bash Lv 5            │
│                          │  ค่าต่อเลเวล (ตาราง)          │
│                          │  [− ][ + ][ Max ]             │
└──────────────────────────┴───────────────────────────────┘
```

**แถบบนต้องติดหน้าจอตลอด** เพราะตัวเลขแต้มคงเหลือคือสิ่งที่ผู้ใช้มองบ่อยที่สุด ถ้าเลื่อนแล้วหายไปจะต้องเลื่อนกลับขึ้นทุกครั้ง

### 5.3 สองมุมมอง สลับได้

เกม Zero เองมี UI ใหม่และปุ่มสลับกลับเป็น Classic UI ผู้เล่นจึงคุ้นทั้งสองแบบอยู่แล้ว ควรให้เลือกได้เหมือนกัน:

- **มุมมองต้นไม้ (ค่าเริ่มต้น)** — ตารางไอคอนพร้อมเส้นโยงเงื่อนไข เห็นภาพรวมว่าสายไหนต่อยอดจากอะไร เหมาะกับการวางแผน
- **มุมมองรายการ** — เรียงเป็นแถวแบบหน้าต่างในเกม ไอคอน + ชื่อ + เลเวล + ปุ่มบวกลบ เหมาะกับคนที่รู้อยู่แล้วว่าจะลงอะไรและอยากลงเร็ว ๆ

จำค่าที่เลือกไว้ใน localStorage

### 5.4 สถานะของโหนด — สี่แบบ ต้องแยกออกจากกันได้โดยไม่พึ่งสีอย่างเดียว

| สถานะ | หน้าตา | เหตุผล |
| --- | --- | --- |
| ยังไม่ลง แต่ลงได้ | ไอคอนสีปกติ ขอบเรืองแสง มีปุ่ม + | ชวนให้กด |
| ลงแล้วบางส่วน | ไอคอนสว่าง ตัวเลข `3/10` เด่น | เห็นทันทีว่าเหลือเท่าไร |
| ลงเต็มแล้ว | ขอบทึบ ตัวเลข `10/10` + เครื่องหมายถูก | ไม่ต้องสนใจอีก |
| ล็อกอยู่ | ไอคอนหม่น + ไอคอนแม่กุญแจ | **ต้องบอกเหตุผลด้วย** |

ข้อสำคัญที่สุดของหน้านี้: **โหนดที่ล็อกต้องบอกว่าล็อกเพราะอะไร** เช่น "ต้องมี Bash Lv 5 (ตอนนี้ 2)" หรือ "ต้องถึง Job Level 40" หรือ "แต้มไม่พอ" — ไม่ใช่แค่ทำให้จาง เพราะคำถามที่ผู้เล่นถามจริง ๆ คือ "ทำไมกดไม่ได้"

### 5.5 กติกาการโต้ตอบ

- คลิกซ้าย = +1, คลิกขวา = −1 (แบบเดียวกับที่คนคุ้นจากเกม)
- Shift + คลิก = ลงเต็ม / ถอดหมด
- กดค้าง = เพิ่มต่อเนื่อง
- **ลงเงื่อนไขให้อัตโนมัติ** พร้อมแจ้งให้เห็นว่าระบบลงอะไรให้บ้าง เช่นข้อความชั่วคราวว่า "ลง Bash Lv 5 ให้อัตโนมัติ (ใช้ไป 5 แต้ม)" — สำคัญมาก ไม่งั้นผู้ใช้จะงงว่าแต้มหายไปไหน
- ลดสกิลต้นทางแล้วสกิลปลายทางถูกถอด ต้องเตือนก่อนถ้าจะถอดหลายตัว
- Undo / Redo ผูกกับ Ctrl+Z / Ctrl+Shift+Z
- hover ที่โหนด = เน้นเส้นเงื่อนไขของมันให้สว่างขึ้น เส้นอื่นจาง

### 5.6 เส้นเชื่อม

วาดด้วย SVG ทับบน CSS grid ไม่ต้องใช้ canvas — จำนวนโหนดต่ออาชีพอยู่ในหลักสิบ ไม่ใช่ปัญหาด้านประสิทธิภาพ

- เส้นจากสกิลต้นทางไปปลายทาง มีหัวลูกศร
- เส้นที่เงื่อนไขครบแล้ว = ทึบ, ยังไม่ครบ = ประ
- ถ้าเงื่อนไขต้องการเลเวลเฉพาะ ให้เขียนตัวเลขกำกับบนเส้น เช่น `Lv 5`

### 5.7 มือถือ

หน้าจอแคบวางตารางแบบเดิมไม่ได้ ให้:

- มุมมองรายการเป็นค่าเริ่มต้นบนมือถือ
- แตะโหนด = เปิด bottom sheet แสดงรายละเอียดและปุ่มบวกลบ
- แถบแต้มคงเหลือติดขอบบน
- ยังเปิดมุมมองต้นไม้ได้แต่ให้เลื่อนแนวนอนและซูมได้

### 5.8 แชร์บิลด์

เข้ารหัสสถานะทั้งหมดลง URL (อาชีพ + เลเวลของแต่ละสกิล) แบบสั้นพอส่งในแชทได้ ไม่ต้องมีระบบสมาชิก เมื่อเปิดลิงก์แล้วให้แสดงเป็นโหมดอ่านก่อน พร้อมปุ่ม "แก้ต่อจากบิลด์นี้"

นี่คือสิ่งที่ทำให้เครื่องมือถูกส่งต่อในกลุ่มและดิสคอร์ด ซึ่งเป็นช่องทางที่เว็บใหม่ต้องการที่สุด

### 5.9 ข้อมูลไม่ครบ ต้องแสดงให้เห็น

ตามหลักที่โปรเจกต์ใช้กับหน้าอื่นอยู่แล้ว: ค่าที่ไม่มีให้แสดง `—` ไม่ใช่เดา และถ้าอาชีพไหนข้อมูล prerequisite ยังไม่ครบ ให้ขึ้นป้ายบนหัวหน้าว่าข้อมูลสายนี้ยังไม่สมบูรณ์ พร้อมบอกว่าขาดกี่สกิล ดีกว่าปล่อยให้ผู้ใช้วางแผนบนข้อมูลผิดแล้วไปเสียแต้มจริงในเกม

### 5.10 การเข้าถึง

- ทุกโหนดต้องโฟกัสด้วยคีย์บอร์ดได้ ลูกศรเลื่อนระหว่างโหนด `+` / `-` ปรับเลเวล
- สถานะล็อกต้องมีไอคอนกำกับ ไม่ใช่แค่สีจาง
- ตัวเลข `3/10` ต้องอ่านออกด้วย screen reader เป็นข้อความเต็ม

## 5.11 ทำอะไรได้ตอนนี้ — v0 ที่ใช้งานได้จริงและดูสมบูรณ์

### ข้อค้นพบที่เปลี่ยนภาพทั้งหมด

แยกสกิล 851 รายการตามอาชีพแล้วพบว่า **ช่องว่าง 418 รายการที่ไม่มีอาชีพผูก ส่วนใหญ่ไม่ใช่ช่องว่างของ Zero** แต่เป็นสกิลของเนื้อหาที่ยังไม่เปิดในเซิร์ฟ ได้แก่สกิลคลาส 3 (Adoramus, Aimed Bolt, Abundance, Aid Berserk Potion) และสกิลโฮมุนคูลุส (Amistr Bulwark)

นอกจากนั้นในไฟล์ยังมีอาชีพที่ผูกไว้แล้วแต่ไม่มีในเกมเลย เช่น Super Novice 52, Expanded Super Novice 47, Ninja 23, Gunslinger 22, Kagerou 22, Oboro 22, Rebellion 20 รวมถึงสกิลคลาส 3 ที่ผูกชื่ออาชีพไว้แล้ว เช่น Lord Knight, Paladin, Assassin Cross — ทั้งหมดนี้ต้องกรองออกจากมุมมองอาชีพเช่นกัน

ส่วนที่ผูกอาชีพแล้วและตรงกับอาชีพที่มีจริงใน Zero มี **370 สกิล ครบทั้ง 19 อาชีพ** และจำนวนต่ออาชีพอยู่ในระดับที่สมเหตุสมผล:

| สาย | คลาส 1 | คลาส 2 |
| --- | --- | --- |
| ดาบ | Swordsman 11 | Knight 18 · Crusader 24 |
| เวท | Mage 15 | Wizard 19 · Sage 32 |
| ธนู | Archer 7 | Hunter 22 · Bard 24 · Dancer 24 |
| โจร | Thief 11 | Assassin 17 · Rogue 23 |
| อาโค | Acolyte 16 | Priest 24 · Monk 22 |
| พ่อค้า | Merchant 12 | Blacksmith 28 · Alchemist 21 |

ตัวเลขคลาส 1 สอดคล้องกับจำนวนสกิลคลาส 1 ที่รู้กันใน RO ทั่วไป ซึ่งเป็นสัญญาณว่าชุดที่ผูกอาชีพแล้วน่าจะครบสำหรับอาชีพเหล่านี้ ไม่ใช่ข้อมูลที่ขาดหาย — แต่ยังต้องยืนยันในเกมอยู่ดี เพราะ Zero ปรับผังสกิลจาก RO เดิมหลายจุด

**แปลว่าข้อมูลที่มีพอทำหน้าที่ดูสมบูรณ์ได้แล้ว** ถ้าเลิกคิดว่าต้องแสดงครบ 851 รายการ

### v0 ที่ควรทำ: หน้าต่างสกิลรายอาชีพ ไม่ใช่ตัววางแผน

ทำเป็น **หน้าเรียกดูที่หน้าตาเหมือนหน้าต่างสกิลในเกม** โดยยังไม่มีการลงแต้ม:

- เลือกอาชีพจากแถบไอคอนด้านบน แล้วแสดงสกิลของอาชีพนั้นเป็นตารางไอคอนแบบหน้าต่างในเกม
- คลิกที่สกิลเปิดรายละเอียดด้านข้าง (ชื่อ ชนิด ธาตุ เลเวลสูงสุด)
- แท็บแยก "ยังไม่เปิดในเซิร์ฟ" สำหรับ 418 รายการที่เหลือ พร้อมคำอธิบายว่าเป็นเนื้อหาที่ยังไม่มาถึง Global
- ตัวกรองชนิด active/passive และช่องค้นหา

**เหตุผลที่ยังไม่ควรใส่การลงแต้มใน v0:** ถ้าให้ลงแต้มโดยไม่มีข้อมูล prerequisite ระบบจะบอกว่าลงสกิลได้ทั้งที่ในเกมลงไม่ได้ นั่นคือการให้คำตอบผิด ซึ่งแย่กว่าการไม่มีฟีเจอร์ หน้าเรียกดูล้วน ๆ ไม่สัญญาอะไรที่ทำไม่ได้ จึงดูสมบูรณ์ในตัวเอง

### สิ่งที่ต้องทำก่อน ไม่งั้นหน้าจะดูพัง

**ไอคอนสกิลยังใช้ไม่ได้** ทั้ง 851 รายการเก็บ path เป็น `/assets/local/catalog/...` ซึ่งเป็น path ของ rozerodb เปิดบนเว็บเราจะ 404 ทั้งหมด

โปรเจกต์มิเรอร์รูปมอนสเตอร์ 522 ไฟล์และรูปไอเทม 1,299 ไฟล์ไว้ใน `public/images/` อยู่แล้ว การมิเรอร์ไอคอนสกิลจึงเป็นงานแบบเดียวกันที่ทำมาแล้วสองรอบ ไม่ใช่เรื่องใหม่

ถ้ายังไม่อยากมิเรอร์ ทางสำรองคือแสดงเป็นบล็อกสีตามธาตุพร้อมอักษรย่อของชื่อสกิล ซึ่งยังดูเป็นระเบียบแต่ไม่เหมือนเกม

### เกณฑ์ว่า v0 เสร็จ

1. เลือกอาชีพได้ครบ 19 อาชีพที่มีในเกม และแต่ละอาชีพแสดงสกิลครบตามจำนวนข้างต้น
2. ไอคอนแสดงได้จริงทุกตัว (มิเรอร์แล้ว) หรือใช้ตัวแทนที่สม่ำเสมอ
3. ค่าที่ไม่มีแสดง `—` ไม่เดา — ชนิดสกิลขาด 448 รายการและธาตุขาด 691 รายการ ต้องยอมรับตรง ๆ
4. มีข้อความบนหน้าบอกว่าหน้านี้คือรายการสกิล ยังไม่ใช่ตัววางแผนบิลด์ และตัววางแผนรอข้อมูลเงื่อนไขสกิล

### เส้นทางจาก v0 ไป v1

เมื่อได้ข้อมูล prerequisite แล้ว หน้าเดิมกลายเป็นตัววางแผนได้โดยไม่ต้องรื้อ เพราะโครงตารางไอคอนรายอาชีพคือโครงเดียวกัน แค่เพิ่มสามอย่าง: ตัวเลขเลเวลบนโหนด ปุ่มบวกลบ และเส้นเชื่อมเงื่อนไข

## 6. ลำดับการทำที่แนะนำ

1. **ยังไม่ต้องทำหน้า tree** ทำ skills browser ตาม v2 หัวข้อ 3.1 ไปก่อน เพราะใช้ข้อมูลที่มีอยู่แล้วและได้ประโยชน์ทันที
2. **หาข้อมูล prerequisite จากไฟล์เกม** เป็นงานแยกที่ต้องทำให้จบก่อน
3. เมื่อได้ข้อมูลแล้ว ทำ engine ก่อน UI — ฟังก์ชันตรวจว่าลงสกิลนี้ได้ไหม ไล่ลงเงื่อนไขอัตโนมัติ ถอดสกิลที่ค้างเงื่อนไข และตรวจลูป พร้อมเทสต์ทุกกรณี
4. ทำมุมมองรายการก่อน (ง่ายกว่าและใช้ได้จริงบนมือถือ) แล้วค่อยเพิ่มมุมมองต้นไม้
5. แชร์ผ่าน URL และ undo/redo เป็นงานสุดท้าย
