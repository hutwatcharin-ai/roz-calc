บันทึกที่ต้องเปิดคู่กันทุกรอบ: `docs/UPDATE-LEDGER.md` (ประกาศที่ทำแล้ว + งานที่มีวันหมดอายุ + ของที่รอ)

- ข้อมูลที่มาจากไฟล์เกมอย่างเดียว ลงเว็บได้ แต่ติดป้ายเล็ก **"จากไฟล์เกม ยังไม่ได้เช็กในเกม"** เฉพาะส่วนนั้น (ไม่ใช่ทั้งหน้า) · owner เช็กในเกมผ่านแล้วค่อยเอาป้ายออก และจดใน ledger
  - เหตุ: 29 ต.ค. ขั้นเควส Gatchaman จากไฟล์เกมพาผู้เล่นเดินผิด
- เวลาในเกมรีเซ็ต 04:00 UTC = **11:00 น. เวลาไทย** · เขียนเวลาไทยเสมอ ห้ามเขียน "04:00" เฉยๆ

## ขั้นตอน

### 0. เปิด ledger ก่อน
1. อ่าน `docs/UPDATE-LEDGER.md`
2. งานในหมวด "วันหมดอายุ" ที่เลยวันแล้ว ทำก่อน (ย้ายโค้ดไปกลุ่มหมดอายุ, ย้ายอีเวนต์ไปกลุ่มจบแล้ว ฯลฯ) แล้วลบแถวนั้นออก
3. ดูหมวด "รอรูป / รอข้อมูล" ว่าแพทช์นี้มีของที่รอหรือยัง

### 1. ประกาศทางการ
1. เปิด https://roz.mygnjoy.com/th/news ผ่าน Chrome ของ owner (อ่านอย่างเดียว)
2. หาเลขประกาศที่ยังไม่อยู่ใน ledger หมวด "ประกาศที่ทำแล้ว"
3. เนื้อหาประกาศเป็นรูป: ดาวน์โหลดรูปจาก assets.mygnjoy.com ลง scratchpad แล้วตัดเป็นช่วงอ่าน · **รูปประกาศไม่เอาขึ้นเว็บ** ใส่ลิงก์ไปหน้าประกาศแทน
4. ประกาศ Discord ที่ค้าง: `npx tsx --env-file=.env.local scripts/discord-inbox.mts list` (ดู "ประกาศ Discord ทางการ → ทำข่าว" ใน CLAUDE.md)

### 2. ไฟล์เกม
- ถ้า owner รัน GrfDiffTool แล้ว (มีโฟลเดอร์ใหม่ใน `D:\Data grf roz\weekly\`) ทำ "แพทช์ลงแล้ว → อ่านไคลเอนต์ใหม่" ข้อ 1–5 ใน CLAUDE.md
- ถ้ายังไม่รัน: ทำส่วนประกาศให้จบก่อน แล้วบอก owner ว่าเหลือส่วนไหน

### 3. เนื้อหาใหม่
- แพทช์/ปิดปรับปรุง: หน้า `/news/patch-<วันที่>` + แถว NEWS
- อีเวนต์/คูปอง: หน้า `/news/events-<ปี-เดือน>` ตามแบบ `/news/events-2026-10` (รูป NPC + `<NaviCopy>` ทุกพิกัด, ขั้นตอนมีเลข, ไอคอนของ, กล่อง REWARD)
- โปรร้าน: หน้า cash shop
- บรรทัดแหล่งที่มาใต้หัวหน้า บอกว่าส่วนไหนมาจากประกาศ ส่วนไหนจากไฟล์เกม

### 4. รูป (ทำพร้อมเนื้อหา ไม่ต้องรอสั่ง)
- ทุก NPC / มอน / ไอเทม ที่หน้าพูดถึง ต้องมีรูปจากไฟล์เกม (PNG/WebP เท่านั้น ไฟล์ดิบห้ามเข้า repo หรือ R2)
  - NPC/มอน: แบบ `scripts/build-event-2026-11-images.py`
  - ไอคอนไอเทม: มากับ `import-new-client-items.py`
  - ไฟล์เกมไม่มีรูป: เว้นไว้ แล้วจดใน ledger หมวด "รอรูป"
- เควสที่เดินหลายจุด: แผนที่ปักหมุดแบบ A (`app/news/events-2026-11/QuestMap.tsx`) · แผนที่เล็กแปลงจาก BMP ไคลเอนต์ไป `public/images/maps/<map>.png` · ตำแหน่ง x/W, 1 − y/H จากขนาด .gat
- การ์ดข่าว: `scripts/build-news-cards.mts` ทุกหน้าข่าวใหม่
- ห้องแต่งตัว: มีคอสตูม/หมวกใหม่ ต้อง `npm run dress-up:build` แล้ว `npm run dress-up:upload` **ก่อน deploy**

### 5. ตามแก้จุดเก่าในเว็บ (2 ชั้น)

**ชั้น 1 — เปิดดูทุกรอบ:**
- หน้าแรก NOW PLAYING (`lib/news.ts`)
- แถว NEWS
- `data/site-updates.json` (งานที่ผู้เล่นเห็น)
- FAQ
- `/news/roadmap` (LANDED, DONE_MONTHS)
- `/guides/codes` (ย้ายโค้ดหมดอายุ)
- หน้าอีเวนต์เดือนนั้น
- หน้าแมพ / แมพที่เปิด (`build-map-availability.mjs`)
- หน้า cash shop
- หน้า guide ที่เขียนว่า "ยังไม่เปิด" (เช่น `/guides/star-gear`)

**ชั้น 2 — ค้นทั้งเว็บด้วยคำจากประกาศ:**
ค้นใน `app/`, `components/`, `data/`, `lib/` ด้วยชื่อระบบ ชื่อแมพ ชื่อ NPC ชื่อไอเทม เวลา วันที่ และคำว่า "ยังไม่เปิด" / "รอ" / "เร็วๆ นี้" · ทุกหน้าที่เจอ เปิดอ่านแล้วตัดสินว่าต้องแก้ไหม

ท้ายข้อนี้เขียนสรุป 3 กอง: จุดที่เจอ / แก้แล้ว / ปล่อยไว้ + เหตุผล (ใส่ในข้อความพรีวิว)

### 6. อัปเดต ledger
- เพิ่มเลขประกาศที่ทำแล้ว
- เพิ่มทุกวันหมดอายุ (อีเวนต์จบ, โค้ดหมด, ร้านถอน, EXP x2)
- เพิ่มของที่รอรูป / รอข้อมูล / ป้าย "ยังไม่ได้เช็กในเกม" ที่ติดไว้

### 7. พรีวิวชุดเดียว → "ขึ้น" ครั้งเดียว
1. `npm run build` → รีสตาร์ต 3178 → ลบ `.next/cache/fetch-cache` ถ้าหน้าอ่าน DB
2. ส่งข้อความพรีวิวเดียว มี:
   - ลิงก์ http://100.108.70.113:3178/... ทุกหน้าที่เปลี่ยน
   - ภาพหน้าจอหน้าหลัก (SendUserFile)
   - รายการว่าข้อไหนมาจากประกาศ ข้อไหนจากไฟล์เกม
   - สรุปจุดที่ตามแก้ (ข้อ 5)
3. owner พิมพ์ "ขึ้น" → deploy ตาม CLAUDE.md (marker ต้องมีเฉพาะบิลด์ใหม่) → curl เช็ก → แปะลิงก์ rozerothai.com ทุกหน้า
4. **ยกเว้นงานด่วน** ที่ผู้เล่นใช้ทันที (โค้ดคูปองใหม่, เวลา EXP x2): ถาม owner ว่าขึ้นแยกก่อนไหม เป็นรายครั้ง
5. หลังขึ้นแล้ว: `scripts/discord-inbox.mts done <id...>` · แพทช์เพิ่มมอน/แมพ → `scripts/discord-inbox.mts names`
